# Backtest engine v1 (Sprint 03)

Code: `services/market-data/src/market_data/` `backtesting/backtest.py` (engine, fill-model comparison, causality check, cost sweep), `backtesting/metrics.py`, `backtesting/research.py` (hashes, storage), `backtesting/luck.py` (luck controls), `api/routers/backtest.py` (Swagger section "Backtest"). Decisions: ADR 0009 (execution model), 0010 (storage and hashes), 0011 (luck control). Worked example with real numbers: [backtest-worked-example.md](backtest-worked-example.md) (generated by `scripts/reports/backtest_worked_example.py`).

## Model in one paragraph
One asset, long-only, fractional shares. At the close of day t the rule SMA(fast) > SMA(slow) sets the target 1 (else 0). The trade fills at the **open of day t+1** (`next_open`). Buys fill at `ref*(1+slippage)`, sells at `ref*(1-slippage)`, commission is a share of the fill value on every fill, both in basis points. Equity is marked at each close. A position open on the last bar is an open trade valued at the last close. Prices are split-adjusted as of the end date; dividends are in returns only with `price_basis = split_dividend` (Sprint 05, below).

## Fill models
| Model | Fill | Realisable | Purpose |
|---|---|---|---|
| `next_open` | open of the day after the signal | yes | default |
| `same_close` | close of the signal day | **no** | teaching mode (look-ahead detector, `POST /backtests/fill-model-comparison`) |

On the loaded real data the unrealisable `same_close` did **not** beat `next_open` (AAPL -5.9 points, SPY -2.7 points at zero cost, see the worked example). The detector therefore flags a method problem; it does not promise a visible inflation on every series. On seeded synthetic data with overnight gaps it does (tested).

## Metrics (conventions)
| Metric | Formula | Undefined (null) when |
|---|---|---|
| total return | `E_n / E_0 - 1` | never (empty or negative equity raises) |
| CAGR | `(E_n / E_0)^(252 / n) - 1`, n = number of daily returns | n < 1 |
| annualised volatility | sample std (ddof 1) of daily returns x sqrt(252) | fewer than 2 returns |
| Sharpe | `mean(r) / std(r) x sqrt(252)`, risk-free rate 0 | std < 1e-12 or fewer than 2 returns |
| max drawdown | min over t of `E_t / max(E_0..E_t) - 1` | never (0 if no fall) |
| exposure | share of days with a position | never |
| trades, win rate, avg pnl, total costs | from the trade list (open trade counted) | win rate and avg pnl null with no trades |
| turnover | (entry value + closed exit value) / average equity | never |
| benchmark | buy-and-hold through the same engine, same fill model and costs, one entry | |

## Accounting identity
`final equity = initial cash + sum(trade pnl)`, pnl net of commission and slippage; tested to 1e-9 on golden cases and on real AAPL.

## Reproducibility hash
`config_hash = sha256(canonical JSON {spec, dataset_fingerprint, engine_version})`; `dataset_fingerprint = sha256` of the exact bars (date, OHLC to 6 decimals, volume); `result_hash = sha256` of the equity curve (6 decimals) and trades. Spec numbers are plain decimal strings so `5` and `5.0` hash alike. Same config + same data + same engine gives the same `result_hash`; a changed bar changes the fingerprint (`data_changed`); a different result on the same data is `engine_mismatch`. Details in ADR 0010. A matching hash proves repeatability, not correctness.

## Cost sweep
`POST /backtests/cost-sweep` reruns the strategy over a grid of slippage values (optionally commission too) and interpolates the **break-even cost** (return reaches 0, or the buy-and-hold return). It describes the sensitivity of one historical path, not a forecast.

## Luck control
`POST /backtests/shuffle-test` runs the same spec on N seeded synthetic paths. `block_bootstrap` keeps each bar's shape, the asset's drift and structure inside blocks, and destroys long-range order. `gbm` keeps mean and volatility of log returns with independent returns. The result ranks the real outcome among the paths. It is a teaching aid, not a significance test; every parameter pair you try is another draw.

## Price basis, source and risk-free rate (Sprint 05)
- **`source`** (default `alpaca`, or `tiingo`) names the price series read from `market.bar_daily`; sources are never mixed (ADR 0013). **`price_basis`** (default `split`, or `split_dividend`) picks the as-of adjustment of Sprint 02. Both are in the spec; they enter `canonical_spec` and the config hash **only when not the defaults**, so every Sprint 03 hash is unchanged (tested against the two saved runs).
- **Total return, causal.** With `split_dividend` the bars before each ex-date are scaled by `1 - cash / (raw close of the last session before the ex-date)`, using only actions with `ex_date <=` the cursor. Because every bar before an ex-date receives the same factor, the SMA signal is unchanged by dividends that are not yet known, and the equity at date t from the full run equals the equity from a run that ends at t (the truncation test passes at 1e-9 on AAPL across the 2020-08-31 split and its dividend ex-dates, and on SPY).
- **Where dividends count.** They enter the return through the adjusted price series: a position held across an ex-date earns the dividend; a flat strategy earns nothing; no cash is paid, there is no reinvestment timing, no tax and no withholding. The default `split` basis ignores dividends entirely.
- **External check.** `adjustment_vs_vendor` compares our split+dividend close with Tiingo's `adjClose` (kept only in the local raw file): the ratio should be nearly constant (it equals the product of vendor adjustments after the window end). Over 21 years the spread (p95/p5 - 1) of that ratio was 0.015% (AAPL), 0.04% (MSFT), 0.09% (SPY), 0.10% (JNJ), 0.14% (KO), 0.18% (XOM), 0.30% (PFE), all inside the 0.5% tolerance fixed in ADR 0013 Appendix A (`GET /sources/adjustment-check/{symbol}`).
- **Excess-return Sharpe.** `excess_sharpe(equity, rf_daily)` = `mean(r - rf) / std(r - rf, ddof=1) x sqrt(252)` with `rf_t = (y / 100) / 252`, where `y` is the last non-null FRED `DGS3MO` (3-month Treasury yield, percent per year) observed strictly **before** day t. With `rf = 0` it equals `sharpe` exactly. `full_run(..., rf=...)` and `risk_free: true` in the API add `sharpe_excess`; the default output is unchanged. The engine's idle cash still earns 0 while the metric subtracts a positive rf, so the excess Sharpe of an in-and-out rule is biased **downward** when rates are positive. This product uses the FRED API but is not endorsed or certified by the Federal Reserve Bank of St. Louis.

## Known limitations
Dividends count only with `price_basis = split_dividend` and only while a position is held (see above); one asset; fractional shares; flat bps costs (no size-dependent impact); idle cash earns 0 and the plain Sharpe uses a risk-free rate of 0 (excess Sharpe is opt-in); no stops or targets (intrabar order unknown); the Alpaca (IEX) window is 2020-07-27 to 2025-12-31 while the Tiingo window starts in 2005 (some names later); survivorship-biased universe; the SMA rule is a test vehicle, not a recommendation. Nothing here is investment advice.

## Price basis comparison (Sprint 05)

Reading the table (SMA 20/50, 1 bp commission + 2 bps slippage, Tiingo data end 2025-12-31). The rule is out of the market part of the time, so it collects fewer dividends than buy and hold; dividends matter little for AAPL and a lot for SPY (about 2 percentage points of CAGR over 21 years for buy and hold, 1.6 for the rule). The source column differs only through the data feed: on the same 5.4 years the two sources give nearby but not identical numbers (IEX-only prints vs consolidated). Not evidence of a profitable strategy; the rule underperforms buy and hold on both symbols in every window.
