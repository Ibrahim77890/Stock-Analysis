# Task 08_03: Gateway lessons module: progress, server-side answer checking, ownership

**Sprint:** 08     **Depends on:** 08_02     **Size:** L
**Concepts to read first:** [08_02](../concepts/08_02_content-as-data-lesson-schemas-validation-and-versioning.md), [08_03](../concepts/08_03_checking-answers-on-the-server-and-idempotent-progress.md)

## Goal
A signed-in learner can list lessons with their own progress, read a lesson without the answer key, answer a question and get a server-side verdict with an explanation, and mark steps read, all idempotently and without seeing anyone else's progress.

## Context
Blueprint Section 24 (the gateway owns users, ownership and progress). Sprint 06 and 07 patterns: 404 for others' objects, whitelisting, plain error messages, per-learner limits.

## What to do
1. Migration (node-pg-migrate, schema `app`): `app.lesson(slug PK, version int, title, summary, minutes, position, content jsonb)`, `app.lesson_question(lesson_slug FK, position, version, prompt, options jsonb)` where `options` holds `text`, `why` and `correct` (the answer key stays in the database), `app.lesson_progress(learner_id FK CASCADE, lesson_slug, step int, PRIMARY KEY (learner_id, lesson_slug, step))`, `app.quiz_answer(answer_id identity PK, learner_id FK CASCADE, lesson_slug, question_position, lesson_version, option_index, correct boolean, created_at)` (append-only by convention). Up and down.
2. Make `npm run seed:lessons` (08_02) write these tables idempotently.
3. Module `src/lessons` with guarded routes: `GET /lessons` (all lessons with the learner's steps read, questions answered correctly, and `done`), `GET /lessons/:slug` (steps and questions with option **texts only**: no `correct`, no `why`), `POST /lessons/:slug/steps/:n/read` (idempotent upsert), `POST /lessons/:slug/questions/:n/answer` (body `{option: int}`).
4. Answer rule: the reply holds `correct` (boolean), the `why` of the **chosen** option, and the index of the correct option **only when the answer was correct or when the learner has already answered this question wrongly twice** (document the rule in the Swagger summary). Every answer is appended to `app.quiz_answer`. Progress for a question is "answered correctly at least once".
5. Unknown slug, step or question number, another learner's rows and malformed numbers give the same 404 body; invalid `option` gives 422; the answer route is limited to 60 per minute per learner (reuse the Sprint 07 limiter; 08_04 makes it durable).
6. Whitelist every reply; add response DTOs; regenerate `docs/02-domain/openapi-gateway.json` and the web types.

## Where to do it
- Folder / file: `apps/api/migrations/`, `apps/api/src/lessons/`, `apps/api/src/dto.ts`, `apps/api/test/lessons.spec.ts`.
- Technology: NestJS, `pg`, Vitest + Supertest.
- Database schema/ownership: `app.lesson*`, `app.quiz_answer` (gateway). Python is not involved.

## Inputs
- The seed from 08_02, the Sprint 06 and 07 gateway modules.

## Deliverables
- Migration, module, DTOs, tests, refreshed OpenAPI.

## Acceptance criteria / tests
- [ ] Migration up, down, up; Python tables untouched.
- [ ] **Answer-key leak (negative):** no reply of `GET /lessons` or `GET /lessons/:slug` contains `correct` or `why` anywhere (scan all six lessons); a first wrong answer does not reveal the correct index.
- [ ] Answering the same question twice with the same option returns the same verdict and leaves **one** progress row; 20 concurrent identical answers leave one progress row and 20 append-only attempts (idempotent progress).
- [ ] Marking the same step read twice (and 20 times concurrently) leaves one row.
- [ ] **Isolation fuzz:** two learners, 100 random attempts on lesson routes: each learner sees only their own progress; unknown and malformed identifiers give identical 404 bodies.
- [ ] Rate limit: the 61st answer in a minute is 429 with `Retry-After`; another learner is unaffected.
- [ ] Lesson version stored with each attempt; re-seeding a lesson with a new version does not rewrite old attempts.
- [ ] Contract test passes and detects a renamed field; `npm run check:python-api` passes.
- [ ] Standing invariants: idempotency (above), reconciliation (progress counts in `GET /lessons` equal the table), replay boundary n/a.

## Out of scope
- Screens (08_05), a leaderboard or scores (the product teaches doubt, not competition), certificates, Python changes.

## Notes for the implementer
Do not compute anything that Python computes. A quiz verdict is a lookup, not statistics, so it stays in the gateway.
