# Task 08_02: Lesson content as validated data: schema, six lessons, idempotent seed

**Sprint:** 08     **Depends on:** none     **Size:** L
**Concepts to read first:** [08_01](../concepts/08_01_learning-design-for-beginners-worked-examples-retrieval-practice-and-feedback.md), [08_02](../concepts/08_02_content-as-data-lesson-schemas-validation-and-versioning.md)

## Goal
Six short beginner lessons exist as JSON files with a schema, are checked by tests for structure and readability, and are loaded into the gateway's database by an idempotent script.

## Context
Sprints 06 and 07 gave learners tools but no path. The blueprint's learning experience (Section 23.2) needs lessons with checks for understanding. Content as data lets tests cover every word (as the glossary already does).

## What to do
1. Create `apps/api/seed/lessons/` with one file per lesson and `lesson.schema.json`. Fields: `slug`, `version` (integer), `title`, `summary`, `minutes` (3 to 8), `steps` (4 to 6: `head`, `body` with `{{slug|label}}` markers, optional `more`, optional `demo` id from this list: `chance-70`, `coin-streaks`, `many-tries`), `questions` (exactly 3: `prompt`, `options` 2 to 4 each with `text` and `why` (the explanation shown after choosing it), exactly one `correct: true`).
2. Write the six lessons in this order, each teaching one idea with one example and ending with the three questions: (1) reading a candle chart, (2) what a probability guess means (70% means wrong 3 times in 10), (3) the Brier score and the coin-flip line, (4) calibration and why few guesses prove little, (5) luck and trying many ideas (streaks, overfitting), (6) costs, buy and hold and the vault (what a backtest cannot tell you). No lesson promises profit or gives advice.
3. Reuse the glossary words (`candle`, `brier-score`, `calibration`, `luck`, `idea-tried`, `vault`, `buy-and-hold`, `basis-point` and others); add any missing term to `apps/api/seed/learning-terms.json`.
4. Write `apps/api/scripts/seed-lessons.ts` (`npm run seed:lessons`): validates every file against the schema, then upserts `app.lesson` and `app.lesson_question` (migration in 08_03 creates them; until then the script's `--validate-only` mode runs the checks). It is idempotent: running it twice reports "unchanged".
5. Tests (`apps/api/test/lessons-content.spec.ts`): every lesson validates; exactly one correct option per question; reading ease 60 or more and no sentence over 25 words in every step, prompt, option and `why`; every `{{slug|label}}` marker resolves to a glossary term (in the seed file or `docs/02-domain/glossary.md`); no banned word ("beats the market", "edge", "profit", "alpha", "guarantee", "winning", "proof"); every `demo` id is on the list; each lesson file name equals its slug.

## Where to do it
- Folder / file: `apps/api/seed/lessons/`, `apps/api/scripts/seed-lessons.ts`, `apps/api/test/lessons-content.spec.ts`, `apps/api/seed/learning-terms.json`.
- Technology: JSON Schema with Ajv (already a dev dependency), TypeScript, Vitest.
- Database schema/ownership: `app.lesson`, `app.lesson_question` (gateway-owned; created in 08_03).

## Inputs
- The glossary, the screen-copy rules (concept 06_08), concept notes of Sprints 06 and 07 for the wording of each idea.

## Deliverables
- Six lesson files, the schema, the seed script, tests, any new glossary terms.

## Acceptance criteria / tests
- [ ] `npm run seed:lessons -- --validate-only` passes on the six lessons.
- [ ] A lesson with two correct options, one with zero, one with 2 steps and one with an unknown demo id are each rejected by the validator (negative tests).
- [ ] A lesson text with jargon fails the reading-ease check (negative test, as in the Sprint 06 copy tests).
- [ ] Every marker resolves to a glossary term; the test fails when one is renamed (negative).
- [ ] Standing invariants: idempotency (seed twice), reproducibility (the files are the only source of lesson text).

## Out of scope
- The database tables and endpoints (08_03), the screens (08_05), the demos (08_06), translations, more than six lessons.

## Notes for the implementer
Write each explanation as if for a friend who has never invested. A wrong option's `why` must say why it is wrong, not only that it is.
