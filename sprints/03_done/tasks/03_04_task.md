# Task 03_04: Engine causality tests and the look-ahead detector

**Sprint:** 03     **Depends on:** 03_02     **Size:** M
**Concepts to read first:** [03_01](../concepts/03_01_backtest-mechanics-and-fill-timing.md), [03_02](../concepts/03_02_moving-average-crossover.md)

## Goal
The engine is proven free of look-ahead by an automatic truncation test, and a function shows learners how much a leaky fill inflates results.

## Context
Blueprint 23.2 "Look-ahead detector (teaching mode)" and 26.3 causality. Sprint 02 proved the data layer; this proves the engine on top of it, including the split-adjustment assumption of ADR 0009.

## What to do
1. Write `check_engine_truncation(spec, conn_or_bars, cut_points)`: for random dates t, equity and position at t from the full run must equal the same values from a run whose bars end at t (for `backtest_from_db`, the run with `end=t`, so the adjustment is recomputed as of t).
2. Run it on synthetic bars and on real AAPL 2020-07-27..2023-12-31 (first stored AAPL bar; the plan assumed 2019) (across the 2020-08-31 split) and SPY.
3. Write a deliberately leaky variant in the test file (centred SMA signal) and show the truncation check fails on it.
4. Implement `compare_fill_models(bars, spec)`: runs `next_open` and `same_close`, returns both metric sets and the difference in total return.
5. Show on synthetic trending-with-gaps data (seeded) that `same_close` beats `next_open`; show on real data what happens (report the number, do not assume the direction).
6. Write 5 to 10 lines in `docs/02-domain/backtest.md` explaining the result and warning that `same_close` is not realisable.

## Where to do it
- Folder / file: `services/market-data/src/market_data/backtest.py` (functions), `tests/test_backtest_causality.py`, `docs/02-domain/backtest.md`.
- Technology: Python, pytest, the Sprint 02 `check_truncation` pattern.
- Database schema/ownership: read-only through `read.get_bars`; the DB test uses `marketlab_test` data loaded by the existing fixtures or skips with a clear reason.

## Inputs
- 03_02 engine; real AAPL and SPY bars (skip with reason when absent).

## Deliverables
- `check_engine_truncation`, `compare_fill_models`, tests, docs section.

## Acceptance criteria / tests
- [ ] Truncation test passes for 50 random cut points on AAPL 2020-07-27..2023-12-31 (first stored AAPL bar; the plan assumed 2019) (including cuts before and after 2020-08-31) with relative tolerance 1e-9.
- [ ] Negative test: the leaky centred-SMA variant fails the same check (the test asserts it fails).
- [ ] Negative test: a variant that fills at the same bar's close while claiming `next_open` is caught by a golden case with a gap.
- [ ] `compare_fill_models` on the seeded synthetic data shows `same_close` total return strictly greater than `next_open`.
- [ ] Real-data comparison numbers are written to the completion note, whatever the direction.
- [ ] Standing invariants: causality, replay boundary (engine with a replay-cursor `end` never reads later bars; asserted by a fuzz of 50 random `end` dates).

## Out of scope
- Leakage detection for arbitrary user code; intrabar paths.

## Notes for the implementer
If the truncation test fails at the split date, the scale-invariance assumption of ADR 0009 is wrong for your implementation (for example a rounding step); fix the engine, not the test.
