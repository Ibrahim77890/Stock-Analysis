# Task 03_05: Persist runs with a reproducibility hash

**Sprint:** 03     **Depends on:** 03_01, 03_03     **Size:** M
**Concepts to read first:** [03_06](../concepts/03_06_reproducibility-hashing.md)

## Goal
A backtest can be saved to `research.*` with a `config_hash` and `result_hash`, and re-running it from the stored config reproduces the same `result_hash` or reports exactly why not.

## Context
Blueprint 23.2 "Reproducibility hash", 26.3 reproducibility.

## What to do
1. Implement `canonical_json(obj)`: sorted keys, no whitespace, floats rendered through a documented rule (decimal strings with fixed digits for costs and cash; dates ISO).
2. Implement `dataset_fingerprint(bars)`: sha256 of canonical CSV text (date, open, high, low, close, volume at 6 decimals) of exactly the bars used.
3. Implement `config_hash(spec, fingerprint, engine_version)` and `result_hash(equity, trades)` (round equity to 6 decimals before hashing).
4. Implement `save_run(conn, spec, result, metrics, benchmark)` writing run, trades and equity in one transaction; if `config_hash` exists, return the existing `run_id` and change nothing.
5. Implement `reproduce_run(conn, run_id)`: reload the spec, rebuild bars for the stored dates, recompute the fingerprint; if it differs return `{"status": "data_changed", ...}` with both fingerprints; else rerun and return `reproduced` or `engine_mismatch` based on `result_hash`.
6. Implement `list_runs`, `get_run`, `get_trades`, `get_equity` read functions.
7. Document the hash recipe in `docs/02-domain/backtest.md`.

## Where to do it
- Folder / file: `services/market-data/src/market_data/research.py` (hashing, save, read, reproduce), `tests/test_research.py`.
- Technology: Python `hashlib`, `json`, psycopg 3.
- Database schema/ownership: writes only `research.*`; reads `market` through `read.py`.

## Inputs
- Migration 0007 (03_01), engine and metrics.

## Deliverables
- `research.py`, tests, docs section.

## Acceptance criteria / tests
- [ ] Key order and `5` vs `5.0` for a cost give the same `config_hash`.
- [ ] Changing any single field (symbol, fast, slow, fill model, commission, slippage, cash, start, end, engine version) changes the hash (parametrised test).
- [ ] Idempotency: saving the same run twice leaves one `backtest_run` row and unchanged trade and equity counts.
- [ ] Reproducibility: `reproduce_run` returns `reproduced` for a saved AAPL run.
- [ ] Negative test: after changing one `volume` in `marketlab_test` the fingerprint changes and `reproduce_run` returns `data_changed`.
- [ ] Negative test: after editing a stored `result_hash` the status is `engine_mismatch`.
- [ ] Standing invariants: idempotency, reproducibility, reconciliation (stored `sum(pnl)` plus cash equals last stored equity).

## Out of scope
- Hashing arbitrary user code; storing shuffle-test or sweep outputs (returned, not stored, this sprint).

## Notes for the implementer
Store the spec exactly as hashed. Never hash Python's `repr` of a dict.
