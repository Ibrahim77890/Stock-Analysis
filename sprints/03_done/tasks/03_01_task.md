# Task 03_01: Design the backtest contract and create the `research` schema

**Sprint:** 03     **Depends on:** none     **Size:** M
**Concepts to read first:** [03_01](../concepts/03_01_backtest-mechanics-and-fill-timing.md), [03_03](../concepts/03_03_transaction-costs-and-sensitivity.md), [03_06](../concepts/03_06_reproducibility-hashing.md)

## Goal
After this task the rules of the backtest (which price is used for what, how costs work, what the result contains) are written down in an ADR and the database has an empty, migrated `research` schema ready to store runs.

## Context
Blueprint 26.4 item 6 (backtest engine v1) and 23.2 (reproducibility hash). Decisions about timing and costs must be made before code, because every later number depends on them. Blueprint 24 says the `research` schema is owned by the Python service.

## What to do
1. Write ADR `docs/04-adr/0009-backtest-execution-model.md` covering: long-only, one asset, fractional shares, starting cash 100,000, signal at close of day t, fill at open of day t+1 (`next_open`), the `same_close` mode as a labelled teaching mode, last-day signal unfilled, prices = split-adjusted as of the run's end date (and why this is safe for scale-invariant rules; dividends excluded, which understates total return), costs formula (commission and slippage in bps on every fill), no stops/targets (intrabar ambiguity deferred).
2. In the same ADR define the exact accounting identity: `final equity = initial cash + sum(trade pnl)`, where pnl is net of both costs.
3. Write ADR `docs/04-adr/0010-research-schema-and-run-storage.md`: tables, ownership (Python migrates and writes; others may read), uniqueness on `config_hash`.
4. Create migration `0007` with `uv run poe migration-new create research schema` and write `upgrade()`/`downgrade()` for: schema `research`; `research.backtest_run`; `research.backtest_trade`; `research.backtest_equity` (columns listed under Deliverables).
5. Run migration up, down, up and compare `\dt research.*` output each time.
6. Add the three tables to `docs/02-domain/data-dictionary.md`.

## Where to do it
- Folder / file: `docs/04-adr/`, `services/market-data/migrations/versions/0007_create_research_schema.py`, `docs/02-domain/data-dictionary.md`.
- Technology: Alembic hand-written SQL via `op.execute`.
- Database schema/ownership: schema `research` (owner: Python service). Do not write to `market`.

## Inputs
- Sprint 02 outputs: `adjust.py`, `indicators.py`, `read.get_bars`.
- No new dataset.

## Deliverables
- ADR 0009 and ADR 0010.
- Migration 0007. Columns:
  - `backtest_run(run_id bigserial PK, config_hash text UNIQUE NOT NULL CHECK length 64, result_hash text NOT NULL, engine_version text NOT NULL, spec jsonb NOT NULL, dataset_fingerprint text NOT NULL, symbol text NOT NULL, first_date date, last_date date, bars_used integer, realisable boolean NOT NULL, metrics jsonb NOT NULL, benchmark_metrics jsonb, created_at timestamptz DEFAULT now())`
  - `backtest_trade(run_id FK ON DELETE CASCADE, trade_no integer, entry_date date, exit_date date, entry_price numeric(18,6), exit_price numeric(18,6), shares numeric(24,8), costs numeric(18,6), pnl numeric(18,6), closed boolean NOT NULL, PRIMARY KEY (run_id, trade_no))` (`closed = false` marks a position still open on the last bar, valued at the last close)
  - `backtest_equity(run_id FK ON DELETE CASCADE, trade_date date, equity numeric(24,8), position smallint CHECK in (0,1), PRIMARY KEY (run_id, trade_date))`
- Data dictionary rows.

## Acceptance criteria / tests
- [ ] `uv run poe migration-heads` shows one head `0007`.
- [ ] Up, down, up leaves identical `\dt research.*` and the down step removes the schema.
- [ ] A DB test inserts a run twice with the same `config_hash` and the second insert is rejected (negative test).
- [ ] A DB test inserts a trade for a missing `run_id` and it is rejected (negative test).
- [ ] The ADR states the accounting identity and the engine version rule ("bump when results can change").
- [ ] Standing invariant: the `market` schema is unchanged (`\dt market.*` identical before and after).

## Out of scope
- Any engine code (03_02). Multiple assets, shorting, leverage, stops.

## Notes for the implementer
Keep the ADRs short; the point is that someone else can check the code against them. Fractional shares avoid rounding noise in golden tests; integer lots are deferred.
