# Task 07_09: Documentation, fresh-database reproduction, wrap-up and next-sprint hand-off

**Sprint:** 07     **Depends on:** 07_01 to 07_08     **Size:** M
**Concepts to read first:** [07_05](../concepts/07_05_protecting-expensive-endpoints.md)

## Goal
Everything built in this sprint is documented, reproducible from a clean database, honestly summarised, and the open items are written down for the next sprint.

## Context
Every earlier sprint ends with this task: documents must match the code, counts must be real, and failures disclosed. This sprint also adds the first feature (the Lab) where a clear user-facing explanation is part of the product.

## What to do
1. **ADR 0017** (Strategy Lab design): the practice window and the vault (length in bars, embargo of 5 bars, one use), adjustment as of the practice end, what counts as a trial and why repeats are not counted, caps and their reasons, the rate limit, whitelisting, and what was rejected (a parameter grid in the browser, unlimited vault resets, showing vault dates).
2. **Domain documents:** `docs/02-domain/lab.md` (what the Lab computes and shows, each card with its source field, the fixed "does not tell you" list, the reading rules for the vault comparison, a worked example from a real run with the numbers), updated `system-overview.md` (Lab data flow), `data-dictionary.md` (`research.lab_study`, `app.learner_study`), `glossary.md` (final count), `README.md` Swagger table (Lab), `.env.example` (`LAB_RUNS_PER_MINUTE`) and the three service READMEs.
3. **Fresh-database reproduction:** drop and rebuild a scratch database from migrations 0001 to 0012 and `app` migrations; reload the stored files; run the Python tests, the gateway tests, the web tests and `lab_fingerprint.py`; compare the fingerprint with the real database's (equal).
4. **Counts and honesty:** run every suite and list real counts (Python with and without the test database, gateway, web); list the checks that were skipped and why; list the orphan test data in the real database.
5. **Completion notes:** one per task in `sprints/07_current/completed/` (`07_01` to `07_09`) in the established form: what was done, evidence, measured numbers, failures found and fixed, what is still open.
6. **Pending items** in `sprints/07_current/pending/`: each unfinished item with a reason, an owner-neutral next step and the task it belongs to (candidates: person walkthrough if no person was available, screen reader, in-memory limiter and trace, token storage, Tiingo licence, learner deletion, Lab with other rules, more than one symbol per study, report export).
7. **Status log:** update `sprints/current_status.md` (Sprint 07 done, with real numbers) and do not touch other sprint folders.
8. **Repository hygiene:** run the secret scan on the files to be shared (no keys, passwords, tokens), check `.gitignore` covers `data/`, `.env`, `node_modules`, `dist`, walk screenshots; confirm what would be staged for GitHub contains only the allowed sprint files (`README.md`, `concepts/`, `tasks/`).
9. Report to the owner: what the Lab shows, what it does not, what to try first, and the open items. Offer to commit; do not commit unasked.

## Where to do it
- Folder / file: `docs/`, `README.md`, `.env.example`, `sprints/07_current/`, `sprints/current_status.md`.
- Technology: Markdown, existing test commands.
- Database schema/ownership: a scratch database for step 3 (dropped afterwards).

## Inputs
- All earlier tasks' results.

## Deliverables
- ADR, domain document, updated docs, completion notes, pending items, status log, reproduction record.

## Acceptance criteria / tests
- [ ] ADR 0017 exists and lists the rejected alternatives.
- [ ] `lab.md` worked example numbers equal a fresh run of the same inputs (checked by script).
- [ ] The fresh-database run passes all suites and the fingerprint equals the real database's.
- [ ] Completion notes exist for all nine tasks and contain real numbers and honest failures.
- [ ] `pending/` lists every unfinished item with a reason.
- [ ] Secret scan finds no key, token, password or `.env` content in shareable files; the staged-file check shows only the allowed sprint files.
- [ ] Documentation counts (terms, endpoints, tests, migrations) match the code (a small script compares them and fails on a mismatch; negative check by editing one number temporarily).
- [ ] Standing invariants: reproducibility (fresh database), reconciliation (docs versus code counts).

## Out of scope
- Starting Sprint 08, deployment, publishing to the internet.

## Notes for the implementer
Say plainly what the Lab cannot do: it does not find strategies that work, and a good practice result followed by a worse vault result is the normal outcome the sprint teaches.
