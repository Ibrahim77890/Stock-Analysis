# Task 07_02: Lab core in Python: studies with a vault, practice runs, tries counted

**Sprint:** 07     **Depends on:** none     **Size:** L
**Concepts to read first:** [07_01](../concepts/07_01_what-a-backtest-shows-and-what-it-does-not.md), [07_02](../concepts/07_02_trying-many-ideas-overfitting-and-the-number-of-tries.md), [07_03](../concepts/07_03_the-vault-out-of-sample-holdout-and-one-use-tests.md), [07_04](../concepts/07_04_luck-controls-for-a-strategy.md), [07_05](../concepts/07_05_protecting-expensive-endpoints.md)

## Goal
The Python service can create a lab study on a stock, run a moving-average rule on the **practice window only** (strategy and buy and hold, cost table, luck control, trial counted), and open the **vault** once, with hard caps and deterministic results.

## Context
Blueprint 9 (backtesting, validation) and 23.2 (cost sweep, shuffle test, overfitting meter, regimes). Sprints 03 and 04 built the engine, shuffle test, trial registry, one-use holdout and overfitting meter; nothing composes them for a person. This task composes them in one new module and adds nothing to the engine.

## What to do
1. Migration `0012` (create `research.lab_study`): `study_id bigint PK FK -> research.study ON DELETE RESTRICT`, `source text` (default `tiingo`), `practice_end date NOT NULL`, `vault_bars int NOT NULL CHECK (vault_bars BETWEEN 120 AND 1500)`, `created_at`. Up, down, up. (`research.study` and `research.trial` from migration 0008 are reused; the study's `family` is `lab_sma` and `name` is free text.)
2. Create package `src/market_data/lab/` with module `study.py` (the only module with SQL on `research.lab_study`; add the structural test). Functions:
   - `eligible_symbols(conn)`: symbols of the source with at least 3,000 stored sessions, with name, first date, bars.
   - `create_lab_study(conn, symbol, source="tiingo", vault_bars=1000, name=None)`: calls `validation.protocol.create_study`, stores `practice_end` = date of the last practice bar (the bar before the vault starts, leaving an embargo of 5 bars between practice end and vault start), returns study id, symbol, window sizes **in bars and years but not the vault dates**.
   - `run_practice(conn, study_id, fast, slow, cost_bps=2.0, seed=1)`: loads bars with `end = practice_end` (adjustment as of that date, `price_basis = split_dividend`), runs the Sprint 03 engine (`next_open`, commission 0, slippage = `cost_bps`), buy and hold on the same bars, a cost table for `[0, 2, 5, 10, 20]` bps (reuse `cost_sweep` for the rule only), the shuffle test with the capped number of block-bootstrap paths (default 100, maximum 200; reuse `luck.shuffle_test`), and returns: rule and buy-and-hold metrics (`total_return`, `cagr`, `max_drawdown`, `exposure`, `trades`, `sharpe`), the equity curves **downsampled to at most 300 points** (always keeping the first and last point) as growth of 100, a yearly table, the cost table, the luck result (percentile, median, 5th and 95th), warnings (fewer than 20 trades; window length), the trial count and, when at least two trials exist, `overfitting_meter`. The run is recorded as a trial (`phase = train`, params `fast`, `slow`, `cost_bps`) **unless an identical `(fast, slow, cost_bps)` trial already exists in the study**, in which case the result is recomputed and returned with `counted = false`.
   - `open_vault(conn, study_id, fast, slow, cost_bps=2.0)`: one use per study through `final_holdout_evaluation` (raises `HoldoutAlreadyUsedError` the second time); runs the rule on the vault bars with `slow` earlier practice bars as warm-up; returns vault metrics, buy and hold on the vault, the practice result of the **same** parameters, and the study's trial count at the time.
   - `study_overview(conn, study_id)`: trials (params, practice total return, sharpe, trades, order), counts, whether the vault is open, and `practice_years`; never the vault dates before the vault is opened.
3. **Caps (authoritative here):** `2 <= fast < slow <= 300`, `0 <= cost_bps <= 50`, at most 200 trials and 1 vault use per study, at most 200 shuffled paths, a maximum of 6,000 bars per run; violations raise `LabLimitError` (HTTP 422 in 07_03).
4. Determinism: identical inputs and seed give identical output (the response carries the config hash from `backtesting.research.config_hash` of the practice spec and dataset fingerprint).
5. Record the measured run time of the largest allowed input (slow = 300, 200 paths) on the 21-year window in the completion note.

## Acceptance criteria / tests
- [ ] Migration up/down/up; `alembic heads` shows `0012`.
- [ ] **Vault leakage (negative test):** after `run_practice`, deleting every market row after `practice_end` and recomputing gives byte-identical results; no key or value of any practice result contains a date after `practice_end`; a spy on the bar reader shows no end date later than `practice_end` was requested.
- [ ] **Adjustment as of the practice end:** on AAPL (splits and dividends inside the vault in a crafted test database) the practice prices equal the prices from a database truncated at `practice_end`.
- [ ] Vault is one-use: the second `open_vault` raises `HoldoutAlreadyUsedError`; before the vault is opened `study_overview` contains no vault date or vault metric (negative test).
- [ ] Trial counting: five distinct runs give `trial_count = 5`; repeating the same `(fast, slow, cost_bps)` returns the same numbers with `counted = false` and the count stays 5; a run with a different cost counts as new.
- [ ] Golden: on a small crafted price series the rule's equity, trades and the buy-and-hold curve equal hand-computed values; the equity curves start at 100 and the downsampled curve keeps the first and last point and has at most 300 points.
- [ ] Caps: `fast >= slow`, `slow = 301`, `cost_bps = 51`, 201 shuffled paths, a 201st trial and a second vault all raise `LabLimitError`; the study table is unchanged after a rejected call.
- [ ] Determinism: two runs with the same seed give identical JSON; the config hash changes when `fast`, `slow` or `cost_bps` change.
- [ ] Structural test: only `lab/study.py` mentions `research.lab_study` in SQL.
- [ ] Standing invariants: causality (truncation above), replay boundary (no vault dates), idempotency (repeat run), reproducibility (seed and hash), reconciliation (trial count equals rows in `research.trial` for the study).

## Benchmark
Measure wall time of one `run_practice` for: (a) slow = 50, 100 paths; (b) slow = 300, 200 paths, on the 5,283-bar window; write p50 and max of 20 runs each to the completion note with the machine details. No target is stated before it is measured.

## Out of scope
- Other rules than the moving-average crossover, parameter grids, walk-forward in the lab, HTTP endpoints (07_03), users (07_04).

## Notes for the implementer
The practice end must be decided when the study is created and never recomputed from "today's" data. Keep the vault length in bars so it is the same for every symbol with enough history; symbols with fewer than 3,000 sessions are not offered (the list says why).
