# Task 02_04: Replay data-access layer and blind view

**Sprint:** 02     **Depends on:** 02_03     **Size:** M
**Concepts to read first:** [02_02 Replay cursor and leakage testing](../concepts/02_02_replay-cursor-and-leakage-testing.md), [02_04 Golden and property testing](../concepts/02_04_golden-and-property-based-testing.md), [02_01 Adjusted prices as-of](../concepts/02_01_adjusted-prices-as-of-and-look-ahead.md)

## Goal
One module is the only code path that reads market bars for replay; it enforces the cursor, and a blind view hides the symbol, real dates and absolute price level.

## Context
Blueprint 23.2 (blind replay) and 26.3 (replay boundary invariant). The `max_date` argument of Sprint 01 becomes a proper cursor object.

## What to do
1. Create a module `replay` with a `ReplaySession(symbol, start, cursor)` object. `cursor` is a date; it can only move forward through `advance(n_sessions=1)` and never backward past its start.
2. Implement `visible_bars(session, adjustment)` using `get_bars(..., max_date=cursor)`; no other function returns bars from this module.
3. Implement `blind_view(bars)`: drop symbol and real dates, label rows `day 1..n`, rebase the first visible adjusted close to 100 (apply the same factor to open, high, low, close).
4. Add a structural test that scans the package source: only `read.py` (and `quality.py` for its own checks, listed explicitly) may contain SQL against `market.bar_daily`; any other module fails the test.
5. Add a fuzz test: 200 random (start, cursor, adjustment) combinations over real symbols; assert `max(trade_date) <= cursor` and that the visible last bar's adjustment does not change when the database is truncated after the cursor (reuse the 02_03 helper).
6. Add a negative test: calling `advance` with a negative number or beyond the last stored session raises an error or stops at the last session (choose one, document it).
7. Add blind-view tests: output contains no symbol string, no date, first close is exactly 100, and returns are identical to the unrebased series.

## Where to do it
- Folder / file: `services/market-data/src/market_data/replay.py`, tests in `services/market-data/tests/`.
- Technology: Python, Polars.
- Database schema/ownership: reads `market` only.

## Inputs
`get_bars` from 02_03.

## Deliverables
- `replay.py`, structural test, fuzz test, blind-view tests, docstring explaining the invariant.

## Acceptance criteria / tests
- [ ] Fuzz test passes for 200 random cursors (seeded; the seed is printed on failure).
- [ ] The structural test fails if a new module queries `market.bar_daily` (demonstrate by a temporary offending file, then remove it).
- [ ] Blind-view output has no symbol/date columns and starts at 100.0.
- [ ] Invariant: replay boundary (26.3) and causality hold for adjusted series.
- [ ] A session cannot move its cursor backward.

## Benchmark
Informational: time for 200 `visible_bars` calls.

## Out of scope
Paper trading, order simulation, sessions persisted in a database, authentication.

## Notes for the implementer
The cursor is a trading date; compare with `<=` and keep everything in exchange-local dates.
