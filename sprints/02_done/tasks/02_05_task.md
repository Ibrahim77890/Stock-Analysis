# Task 02_05: Returns and causal indicators with a truncation test

**Sprint:** 02     **Depends on:** 02_03     **Size:** M
**Concepts to read first:** [02_03 Returns and causal indicators](../concepts/02_03_returns-and-causal-indicators.md), [02_04 Golden and property testing](../concepts/02_04_golden-and-property-based-testing.md)

## Goal
Simple and log returns, SMA, EMA and rolling volatility exist as pure functions, each proven causal by an automatic truncation test.

## Context
Blueprint 23.3 item 4 and standing invariant "Causality" (26.3). Later backtests may only use these functions.

## What to do
1. Create a module `indicators` with pure functions over a Polars frame sorted by date for one instrument: `simple_return`, `log_return`, `sma(n)`, `ema(n)`, `rolling_volatility(n, annualise=True)`.
2. Define the contract: same length as the input, leading nulls for the warm-up, no fill, input must be sorted ascending (raise otherwise).
3. Document the EMA seeding rule (first value = first close) and the volatility convention (sample std, `sqrt(252)`).
4. Write golden tests with hand-computed numbers: closes 10, 11, 12, 13 gives SMA(3) of null, null, 11, 12; returns of 100 -> 102 is +2%.
5. Cross-check SMA and EMA against Polars built-ins on 3 real symbols (adjusted as of the last date).
6. Write the truncation test: for each indicator, 100 random cut points `t` on AAPL: `f(full)[t] == f(full[:t+1])[t]`.
7. Write the negative test: a leaky indicator using `rolling_mean(center=True)` must fail the same truncation test.
8. Write a test that raw-price returns across the AAPL split are about -74% while adjusted returns are not, to show why indicators take adjusted input.

## Where to do it
- Folder / file: `services/market-data/src/market_data/indicators.py`, tests in `services/market-data/tests/`.
- Technology: Python, Polars.
- Database schema/ownership: none.

## Inputs
Adjusted bars from 02_03.

## Deliverables
- `indicators.py`, golden/cross-check/truncation tests, a short section in the data dictionary or a new `docs/02-domain/indicators.md` with the formulas.

## Acceptance criteria / tests
- [ ] Golden values match hand-computed numbers exactly.
- [ ] Truncation test passes for all five functions at 100 random cut points (seeded).
- [ ] The leaky `center=True` indicator fails the truncation test.
- [ ] An unsorted input raises an error.
- [ ] Standing invariant: causality (26.3).

## Benchmark
Informational: time to compute all indicators for one symbol (about 1,400 rows) and for all 53 symbols.

## Out of scope
RSI, MACD, Bollinger, chart rendering, signals.

## Notes for the implementer
`ewm_mean` has an `adjust` option; pick the recursive form (`adjust=False`) to match the formula in the concept note.
