# Task 02_01: Close the Sprint 01 loose ends

**Sprint:** 02     **Depends on:** none (Sprint 01 is done)     **Size:** M
**Concepts to read first:** [02_06 Indexing for cross-sectional queries](../concepts/02_06_indexing-for-cross-sectional-queries.md), [02_07 Feeds, volume and lineage](../concepts/02_07_data-feeds-volume-and-lineage.md), [01_08 Benchmarking](../../01_done/concepts/01_08_benchmarking-methodology.md)

## Goal
The four items Sprint 01 left open are resolved with evidence: licence terms read, a cold benchmark run recorded, the cross-section index decision made with numbers, and a real-data `get_bars` test in the suite.

## Context
`current_status.md` lists these as open risks and technical debt. They affect trust in the data (licence, window) and the decision "PostgreSQL alone is enough" (ADR 0002).

## What to do
1. For each source in the data dictionary Sources table (Alpaca, Kaggle, Stooq, SEC EDGAR, yfinance), open the provider's actual terms page, copy the one sentence about use/redistribution, and replace "terms unclear". If a page cannot be read, keep "terms unclear" and write why. Fill the retrieval date.
2. Update ADR 0003 with the licence position that follows from step 1.
3. On the `bench` schema, run `uv run market-data bench-run` (warm) twice more and report the spread (min and max of each p50).
4. Restart the PostgreSQL service (administrator rights needed; the human does this), then run `uv run market-data bench-run --cold` and `bench-report`; keep the hand-written conclusion.
5. Create `CREATE INDEX bench_bar_daily_date_idx ON bench.bar_daily (trade_date, instrument_id) INCLUDE (close)` (after `VACUUM ANALYZE`), re-run all four workloads with the same seed, and save `EXPLAIN (ANALYZE, BUFFERS)` for W3.
6. Measure the index size and the load throughput with and without this index (load into a fresh schema both ways).
7. Write the decision (add the index to `market.bar_daily` via migration `0007`: yes/no) in the benchmark report and in ADR 0002, quoting the numbers.
8. Add a pytest that loads nothing but reads the real `marketlab` data: `get_bars` AAPL 2020-08-25..2020-09-04 equals the raw Parquet rows. It must skip when the real data is absent.
9. Record the effective data window (2018-04-25 start) in the data dictionary header and decide in one paragraph whether to try Alpaca's SIP feed in a later sprint.

## Where to do it
- Folder / file: `docs/02-domain/data-dictionary.md`, `docs/04-adr/`, `docs/03-benchmarks/`, `services/market-data/tests/`.
- Technology: Markdown, existing `bench` CLI, PostgreSQL.
- Database schema/ownership: `bench` only for experiments; `market` changes only if step 7 says yes (then a new migration `0007`).

## Inputs
Sprint 01 benchmark report; data dictionary; `data/raw/alpaca/bars_1d/AAPL.parquet`.

## Deliverables
- Sources table with quoted sentences or reasons; updated ADR 0003.
- Benchmark report with cold run, run spread, index experiment and the decision.
- `tests/test_real_data.py`.

## Acceptance criteria / tests
- [ ] Every Sources row has a quoted sentence or "terms unclear" plus a reason, and a retrieval date.
- [ ] The benchmark report has a cold row and a warm row for W1-W4 and states how the cold run was produced.
- [ ] W3 results with and without the index are in one table with the same seed, plus index size and load rows/s for both.
- [ ] The report states yes/no for the new index and no number is claimed without a table row.
- [ ] `uv run pytest` passes; the real-data test passes when data is present and is skipped (not failed) when absent.
- [ ] Negative test: a modified expected row (one price changed in the test) makes the real-data test fail.

## Benchmark
Same protocol as Sprint 01: 20 warm-up and 200 timed queries per workload, p50/p95/p99/mean, hardware recorded.

## Out of scope
Partitioning, BRIN, DuckDB or ClickHouse comparisons, changing the loader.

## Notes for the implementer
Do not rely on memory for licence wording: read the page. Close other programs during benchmarks; Sprint 01 runs differed by up to 1.8x on a busy desktop.
