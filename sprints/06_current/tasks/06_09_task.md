# Task 06_09: Episode screen: blind chart, a three-step coach and the guess form

**Sprint:** 06     **Depends on:** 06_08     **Size:** L
**Concepts to read first:** [06_08](../concepts/06_08_designing-for-novices-plain-language-and-a-light-theme.md), [06_01](../concepts/06_01_hindsight-bias-and-what-blind-must-hide.md), [06_02](../concepts/06_02_probability-forecasts-proper-scoring-and-brier-score.md)

## Goal
A beginner starts an episode, reads a chart whose name, dates and price level are hidden, makes guesses with a probability, moves forward, and watches each guess get its answer, guided at every step in plain words.

## Context
Blueprint 5.2 (Market Replay) and 23.2 (blind replay, prediction scoring). The gateway owns access; Python owns the numbers; the page only shows state and sends commands.

## What to do
1. **Start panel:** three choices written for beginners: "Real prices or made-up prices? Let MarketLab surprise me" (mixed, default), "Real only", "Made-up only"; length ("About one year, 250 days" default; shorter options); an optional "Seed" under "Show more". A short callout: "The name, the dates and the price level are hidden until the end. That way you cannot cheat from memory." Button "Start" calls `POST /episodes`. A list "Your episodes" (from `GET /episodes`) lets the learner resume an open one.
2. **Three-step coach** across the top of the episode screen, always visible: **1 Look** ("Study the chart. Each box is one day."), **2 Guess** ("Will the price be higher in a few days? Say how sure you are."), **3 Move on** ("Move forward and see if you were right."). The current step is highlighted and a one-sentence hint changes with what the learner did last. A "What is a candle?" `Term` explains open, high, low, close with a tiny labelled picture (SVG).
3. **Chart** (Lightweight Charts): candlesticks of `day` 1..n, x-axis labels "Day 87", price axis labelled "Price (starts at 100)", an optional relative-volume bar series under "Show more" (label "Trading activity compared with the first days"). Up and down candles use the tokens **and** the legend says "Up day / Down day" with arrows. A text summary table of the last 10 days sits below the chart (accessible alternative). Credit line as in the footer.
4. **Guess form:** "How far ahead?" as three radio cards ("Next day", "In 5 days", "In 10 days"), "How likely is it that the price is higher then?" as a slider with a big number in percent and the words "50% = no idea", "90% = very sure". A live sentence: "You are saying: 7 out of 10 times I would be right about 'higher'." A clear note: "You cannot change a guess after you send it." Submit button "Send my guess". Disabled with a reason when the horizon goes past the end of the episode.
5. **Move on:** buttons "Next day" and "5 days" (calls `POST /advance`), keyboard shortcut shown on screen. After each advance the bars, the guess list and the day counter reload from the server.
6. **Your guesses** list: day made, how far ahead, your percentage, status in words ("Waiting", "Answered", "Not counted"), and for answered ones "The price went up" / "The price did not go up" with "You were right" / "You were off" (words and arrows, not colour only). A one-line tip appears after the first answered guess ("One guess tells you almost nothing. Scores need many guesses.").
7. **Status sentence** always visible: "Episode 3 - day 87 of 250 - 4 guesses waiting - name, dates and price level still hidden."
8. Loading, empty and error states in plain sentences; no uncaught promise rejections; a visible message when the gateway is unreachable ("MarketLab cannot reach its server. Is it running?").
9. "Finish and see my score" opens a confirmation panel in the page (not a browser dialog) explaining what happens, then goes to the score screen (06_10).

## Where to do it
- Folder / file: `apps/web/src/` (components `StartPanel`, `EpisodeList`, `Coach`, `EpisodeChart`, `CandleHelp`, `GuessForm`, `GuessList`, `StatusLine`; copy in `src/copy/episode.ts`).
- Technology: React, TypeScript, Lightweight Charts, generated types.
- Database schema/ownership: none.

## Inputs
- Gateway learning endpoints (06_07).

## Deliverables
- Working episode screen with component tests and plain-language copy that passes `check:copy`.

## Acceptance criteria / tests
- [ ] Component tests (API mocked): the slider rejects values outside 1 to 99 and the live sentence matches the value (70% shows "7 out of 10"); double click on "Send my guess" calls the API once; an already-recorded reply shows "You already sent this guess"; options beyond the end are disabled with a reason.
- [ ] The coach highlights step 1 on load, step 2 after the form is touched, step 3 after a guess is sent (state test).
- [ ] **No identity in the DOM (negative):** render the screen with blind mock data; the text contains no ISO date, no 4-digit year token, no ticker-like capitals. A mock reply that wrongly contains `symbol` and `start_date` is not rendered (components read only typed fields).
- [ ] The x-axis tick formatter returns "Day N" for integers; the price axis title reads "Price (starts at 100)".
- [ ] After a mocked advance a "Waiting" guess becomes "Answered" with the words "went up" or "did not go up" and "You were right/off".
- [ ] Up/down are conveyed with words and arrows (test checks the legend and list text).
- [ ] The status sentence updates after each command (test).
- [ ] `npm run build`, `npm test`, `npm run check:api`, `npm run check:copy` pass.
- [ ] Manual check recorded: run the gateway, Python and `npm run dev`; register; start a mixed episode; advance 60 days; send three guesses; watch one answer; reload the page and resume; write what you saw.
- [ ] Standing invariants: replay boundary (the page never asks for bars beyond the cursor because the server never returns them; the day counter equals the number of candles), idempotency (double submit).

## Out of scope
- Score and reveal screens (06_10), drawing tools, indicators, trade orders, other timeframes.

## Notes for the implementer
After every command re-read state from the server instead of patching local state. Keep the chart in one component with plain props and mock `lightweight-charts` in tests (jsdom has no canvas).
