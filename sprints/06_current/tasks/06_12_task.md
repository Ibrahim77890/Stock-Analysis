# Task 06_12: Cross-layer checks: leak fuzz, learner isolation, end-to-end, latency and a beginner walkthrough

**Sprint:** 06     **Depends on:** 06_11     **Size:** M
**Concepts to read first:** [06_01](../concepts/06_01_hindsight-bias-and-what-blind-must-hide.md), [06_05](../concepts/06_05_precommitment-append-only-records-and-resolving-outcomes.md), [06_07](../concepts/06_07_two-backends-one-contract-nestjs-gateway-and-python-analytics.md), [06_08](../concepts/06_08_designing-for-novices-plain-language-and-a-light-theme.md)

## Goal
The promises of the learning loop are tested across all three layers: nothing identifying leaves before the reveal, learners cannot see each other's episodes, a whole session works end to end through the real gateway and the real Python service, response times are measured, and a real beginner can follow a written walkthrough.

## Context
Standing invariants (blueprint 26.3), the product principle (23.1) and the open item "API latency unmeasured". Earlier tasks tested their own pieces; this task tests the seams.

## What to do
1. **Identity-leak fuzz through the public API:** start the real Python service (on a spare port, throwaway database, `INTERNAL_API_TOKEN` set) and the NestJS app in-process against it. Create 100 seeded episodes (real and synthetic), drive each through random advances and guesses, and after every call scan every non-reveal response (bodies, error bodies, headers, the OpenAPI examples) for identity: symbol, company name, sector, year tokens 2005 to 2025 in strings, ISO dates, raw closes and raw volumes from `market.bar_daily`, source names, `factor`, `as_of`, `cursor` as a date.
2. **Learner-isolation fuzz:** three learners, 300 random cross-access attempts over every episode route; every attempt returns 404 (or 401 without a token); owners get 200; the Python mock/real service records zero calls for refused requests.
3. **Direct-access check:** with `INTERNAL_API_TOKEN` set, every Python Learning endpoint refuses a call without the header (401), so the browser path is the only path.
4. **End-to-end through the gateway:** one Vitest e2e drives the same flow as the UI: register, login, create, bars, advance, guess at 1/5/10, resolve, score, reveal, progress, glossary, trace, system; every response is validated against the committed OpenAPI contract (JSON-schema check); a response with an extra undeclared identity field fails validation (negative test).
5. **Latency:** script `apps/api/scripts/latency.ts` measures p50/p95/p99 over 200 sequential calls each for `GET /episodes/:id/bars` (250-bar real episode), `POST /episodes/:id/advance`, `POST /episodes/:id/predictions`, `GET /episodes/:id/score` (30 guesses, 5,000 shuffles), once **through the gateway** and once **directly against Python** (with the internal token), so the gateway overhead is visible. Write `docs/03-benchmarks/benchmark-02-learning-api-latency.md` with machine details, call counts and dataset size. Report numbers as measured; state no target.
6. **Beginner walkthrough:** write `docs/02-domain/learning-walkthrough.md`: 14 numbered steps (start the three services, open the page, create an account, take the tour, open a word's definition, start a mixed episode, advance, send a guess at each distance, double-click send, reload and resume, finish and reveal, read the score card, read the data trail, open "Under the hood"), each with the expected result. Then have **someone who did not build it** (ask the owner or a friend) follow it with no help and record, per step, pass/fail, how long it took, and the places where they hesitated or misread something. The implementer follows it too. Each hesitation becomes a wording or layout fix, or an item in `pending/`.
7. **Accessibility pass:** keyboard-only completion of steps 3 to 9; contrast ratios of the five most used text/background pairs computed and recorded (at least 4.5:1); screen-reader labels spot-checked with the browser's accessibility tree; reading ease of all screen copy recorded (60 or more).

## Where to do it
- Folder / file: `apps/api/test/e2e/` (leak, isolation, end-to-end), `apps/api/scripts/latency.ts`, `docs/03-benchmarks/`, `docs/02-domain/learning-walkthrough.md`.
- Technology: Vitest, Supertest, `child_process` to start Python, `ajv` (JSON-schema validation; add as a dev dependency and record the version), Node `fetch`.
- Database schema/ownership: tests use the throwaway database; the latency script uses the real database and creates anonymous episodes there (count them in the note).

## Inputs
- All Sprint 06 outputs; the Python virtual environment `.venv` (the e2e starts it with `.venv/Scripts/python.exe -m market_data.cli serve`).

## Deliverables
- Leak, isolation, direct-access and end-to-end tests; latency page; walkthrough with recorded results; accessibility note.

## Acceptance criteria / tests
- [ ] Leak fuzz passes with zero findings on 100 episodes; a deliberately leaky variant (a test double that adds `symbol` to a bars reply) makes the scan fail (negative test), including when the leak is in a header.
- [ ] Isolation fuzz passes with zero cross-learner successes and zero upstream calls for refused requests.
- [ ] Python Learning endpoints return 401 without the internal token and work with it.
- [ ] The end-to-end test passes and validates every response against the contract; the extra-field case fails validation.
- [ ] The latency page exists with p50/p95/p99 for four calls, both paths, call counts, dataset size and machine; the script is reproducible.
- [ ] The walkthrough has a recorded result for each of the 14 steps from at least one person who did not build the app; all pass, or each failure/hesitation is fixed or listed in `pending/` with a reason.
- [ ] Keyboard-only run succeeds; contrast and reading-ease numbers recorded and meet the thresholds.
- [ ] Python suite (with and without `TEST_DATABASE_URL`), gateway tests and web tests all run; counts recorded.
- [ ] Standing invariants: replay boundary, idempotency, reproducibility, reconciliation and causality each have at least one named test listed in the note.

## Benchmark
What: p50/p95/p99 latency of four calls, 200 sequential calls each, loopback, warm cache, gateway vs direct. Hardware: record CPU, RAM, OS, Node and Python versions. Output: `docs/03-benchmarks/benchmark-02-learning-api-latency.md`. Do not claim numbers before they are measured.

## Out of scope
- Browser automation (Playwright; deferred, the walkthrough is the browser check), load testing, penetration testing beyond the checks above.

## Notes for the implementer
If the scan finds a leak, fix the server, not the scan. A stray date inside an error message counts. The point of the beginner walkthrough is the beginner: do not coach them.
