# Task 06_05: Score and reveal endpoints, lineage for the revealed episode, Swagger "Learning"

**Sprint:** 06     **Depends on:** 06_03, 06_04     **Size:** M
**Concepts to read first:** [06_05](../concepts/06_05_precommitment-append-only-records-and-resolving-outcomes.md), [06_01](../concepts/06_01_hindsight-bias-and-what-blind-must-hide.md), [06_02](../concepts/06_02_probability-forecasts-proper-scoring-and-brier-score.md), [06_03](../concepts/06_03_calibration-reliability-diagrams-and-sample-size.md), [06_04](../concepts/06_04_overconfidence-luck-and-the-permutation-check.md)

## Goal
Every function from tasks 06_02 to 06_04 can be tried by hand in Swagger, a learner can ask for the current score at any time, and a one-way reveal ends the episode and shows what it was, together with where the data came from and what to distrust about them.

## Context
Blueprint 23.2 (blind replay reveal; data lineage panel) and 23.3 item 3 (universe caveat). Continues ADR 0007 (Swagger for every function).

## What to do
1. `GET /episodes/{id}/score`: calls `scoring.summarise` on the **resolved** predictions of one episode; also returns counts `resolved`, `void`, `pending`. Allowed on open and revealed episodes. Never includes identity.
2. `GET /learning/summary` and `POST /learning/summary` (body `episode_ids`, a list of at most 500 ids): the same summary over all resolved predictions of all episodes, or only of the listed ids (the gateway passes the ids a learner owns; unknown ids are ignored), plus a split by episode kind (real vs synthetic) **only for revealed episodes** (the kind of an open mixed episode stays hidden), and by horizon.
3. `POST /episodes/{id}/reveal` (one way, idempotent: a second call returns the same body): sets status `revealed`, voids pending predictions, and returns `kind`, and for real episodes the symbol, company name, sector, first and last real date, source and a lineage panel; for synthetic episodes the seed, volatility and the statement "this series was generated; no market date or symbol exists".
4. Extend `lineage.lineage` with a `source` parameter (default `alpaca`, so existing output is unchanged): for `tiingo` report provider `tiingo`, feed "consolidated US prices (all venues)", the manifest hash from `data/raw/tiingo/bars_1d/`, the quality counts of the episode window, and the caveats: universe survivorship, adjustment method (split as of the final cursor), and the licence line "Tiingo data: internal use only; do not share this page".
5. **Internal access.** These endpoints are called by the NestJS gateway, never by the browser. When the environment variable `INTERNAL_API_TOKEN` is set, every Learning endpoint requires the header `X-Internal-Token` with that value (compared in constant time) and answers 401 without it; when it is unset (plain local Swagger use) the check is off and the OpenAPI description says so. Add a placeholder to `.env.example` if 06_01 has not (it has).
6. Swagger: summaries name the function, the tag description says which endpoints write (`POST /episodes`, `/advance`, `/predictions`, `/reveal`), and the OpenAPI contract is refreshed (`market-data export-openapi`). A test lists every Sprint 06 backend function with its endpoint.
7. Add the end-to-end API test: create a synthetic episode with a fixed seed, make predictions at three horizons, advance until they resolve, read the score (compare with a hand computation from the stored closes), reveal, read the score again (unchanged for resolved ones, pending now void).

## Acceptance criteria / tests
- [ ] Inventory test: every Sprint 06 function (create, get, bars, advance, add_prediction, list_predictions, score, summary, reveal) maps to an endpoint in the OpenAPI document.
- [ ] End-to-end test as in step 6 passes; the Brier score equals the hand value.
- [ ] **No identity before reveal:** the JSON of every endpoint except `reveal` (50 seeded real episodes, including `score`, `summary`, `predictions`) contains no symbol, name, year token, ISO date or absolute price; after `reveal` the identity fields are present and equal the stored episode.
- [ ] Reveal is one-way and idempotent: second call returns the same body; after reveal `advance` and `predictions` return 409; pending predictions are void and the counts reconcile (`resolved + void + pending = total`).
- [ ] The summary's real/synthetic split excludes episodes that are still open (negative test: with one open mixed episode and one revealed one, only the revealed one is split).
- [ ] Existing replay and lineage tests pass unchanged (`lineage(..., source="alpaca")` output identical).
- [ ] Contract test passes; renaming a field is detected (existing negative test still passes).
- [ ] With `INTERNAL_API_TOKEN` set, a Learning call without the header or with a wrong one returns 401 (negative test) and with the right one succeeds; with it unset the endpoints work as before; the token never appears in a response or log line.
- [ ] `POST /learning/summary` with the ids of one learner's episodes ignores other episodes (two-owner test using two episode sets).
- [ ] `score` on an episode with 29 resolved predictions carries the "too few" warning; with 30 it does not.
- [ ] Start `market-data serve` (loopback only) and call each new endpoint once; record that you did.
- [ ] Standing invariants: replay boundary, idempotency, reconciliation, reproducibility (same seed, same predictions, same score).
