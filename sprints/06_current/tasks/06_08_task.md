# Task 06_08: Web app foundation: light theme, beginner shell, login, guided tour and term help

**Sprint:** 06     **Depends on:** 06_07     **Size:** L
**Concepts to read first:** [06_08](../concepts/06_08_designing-for-novices-plain-language-and-a-light-theme.md), [06_06](../concepts/06_06_a-typed-frontend-over-a-typed-api.md)

## Goal
A light-themed, beginner-friendly web app exists: a learner can register, log in, take a short guided tour, open any technical word to read a plain definition, and navigate to the (still empty) learning screens.

## Context
Blueprint Section 24 (simple TypeScript SPA) and 23.4 (glossary as data, mechanics vs interpretation, small mastery checks). The owner asked for a beginner-friendly, light-coloured UI; dark mode is out of scope for this sprint.

## What to do
1. Scaffold `apps/web/` (suggest this folder; record the choice) with the Vite `react-ts` template; pin exact versions (at least two weeks old) for `react`, `react-dom`, `react-router-dom`, `vite`, `typescript`, `lightweight-charts`, `openapi-typescript`, `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/user-event`; commit `package-lock.json`.
2. Typed client: `npm run gen:api` runs `openapi-typescript` on `../../docs/02-domain/openapi-gateway.json` into `src/api/schema.d.ts`; `npm run check:api` fails if the committed file is stale; `src/api/client.ts` is a small fetch wrapper (base URL from `VITE_API_BASE`, default `http://127.0.0.1:3000`; attaches the bearer token; turns errors into a typed `ApiError` with a friendly message; never logs tokens).
3. **Light design system** in `src/styles/tokens.css`: one palette as CSS variables (background, surface, text, muted text, border, accent, up, down, warning, focus ring), `color-scheme: light` on `:root`, **no** `prefers-color-scheme: dark` rules, one readable font stack (system fonts), a base size of at least 16 px, generous spacing, visible focus outlines. Contrast: normal text at least 4.5:1, large text and controls at least 3:1.
4. Small component set with typed props: `Button`, `Card`, `Callout` (info / tip / careful, each with an icon and a label word), `Stat` (big number + one-line meaning), `Stepper`, `Term` (inline word that opens an inline definition panel, not a modal), `Tour`, `EmptyState`, `Loading`, `ErrorMessage`.
5. Shell and routes (`react-router`): Home ("What is MarketLab? Three things you will learn"), Learn (empty placeholder), Score (placeholder), Glossary (searchable list from `GET /glossary`), Sign in / Create account. A top bar with the learner's name and "Sign out", and a visible "Need help?" link to the tour.
6. Login and registration forms: labels above fields, the password rules written before the user types ("10 or more characters; a few random words is fine"), friendly error messages from the API, a "Show password" checkbox, the form works with the keyboard only. Token kept in memory and `sessionStorage` (never `localStorage`, never in a URL); signing out clears it; a 401 anywhere sends the user to sign in with a message.
7. `Term` component: given a slug it loads `GET /glossary/:slug` (cached), shows the plain definition and example, and has a "More" link to the glossary page. Technical words in all screen text use it.
8. **Guided tour** (4 to 6 steps, skippable, reopenable): what the chart shows, what a "guess" is, why you cannot change a guess, how scoring works, what "reveal" does. Shown on first sign-in (remember in `sessionStorage`).
9. **Copy guide** `apps/web/COPY_GUIDE.md` (10 rules: short sentences, everyday words, define terms where used, say "in this sample", no "edge/profit/skill" claims, numbers always with a meaning, etc.) and a script `npm run check:copy` computing the Flesch reading-ease score of each text block in `src/copy/*.ts`; fail below 60 on average or any sentence over 25 words.
10. Footer on every page: "Charts by TradingView Lightweight Charts" with a link, plus "For learning. Not investment advice."

## Acceptance criteria / tests
- [ ] `npm ci && npm run build && npm test && npm run check:api && npm run check:copy` pass from a clean checkout.
- [ ] **Light only (test):** the built CSS contains `color-scheme: light` and contains no `prefers-color-scheme: dark`.
- [ ] **Contrast (test):** a unit test computes the contrast ratio of every foreground/background token pair used for text (4.5:1) and for interface components and focus ring (3:1) and passes.
- [ ] Colour is never the only signal: the `Callout` always shows its label word; the up/down tokens are used only together with an arrow or the words "up"/"not up" (test of the components that use them).
- [ ] Auth component tests (API mocked): registration shows the password rules before input; a 409 shows "That name is taken"; a 401 shows the friendly message; the token is stored in `sessionStorage` only (assert `localStorage` untouched and no token in the URL); sign out clears it.
- [ ] `Term` test: opening a term shows the definition, pressing Escape closes it, it is reachable and operable with the keyboard, and it has an accessible name.
- [ ] Tour test: appears once on first sign-in, can be skipped, and reopened from "Need help?".
- [ ] Copy check passes, and a deliberately jargon-heavy sample paragraph fails it (negative test).
- [ ] Axe-style checks that can be automated in jsdom pass: every input has a label, every button has a name, headings are in order.
- [ ] Standing invariant: reproducibility (lock file; generated types deterministic).

## Out of scope
- The episode, score and visibility screens (06_09 to 06_11), dark mode, translations, mobile-specific layouts beyond a single responsive column, Playwright.

## Notes for the implementer
Write the words first, then the components. Read each screen aloud: if you would not say it to a friend who has never seen a chart, rewrite it.
