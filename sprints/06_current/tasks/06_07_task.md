# Task 06_07: NestJS learning gateway, glossary and request trace

**Sprint:** 06     **Depends on:** 06_05, 06_06     **Size:** L
**Concepts to read first:** [06_07](../concepts/06_07_two-backends-one-contract-nestjs-gateway-and-python-analytics.md), [06_01](../concepts/06_01_hindsight-bias-and-what-blind-must-hide.md), [06_08](../concepts/06_08_designing-for-novices-plain-language-and-a-light-theme.md)

## Goal
A logged-in learner can run the whole learning loop through NestJS only: every episode belongs to exactly one learner, nothing identifying leaves before the reveal, definitions of terms are served as data, and the learner can see a trace of what their requests did.

## Context
Blueprint Section 24 (NestJS acts as the public gateway: replay sessions, lessons, progress) and 23.4 (glossary as a first-class data model, not a static page). The "request trace" feeds the visibility page of 06_11.

## What to do
1. **Learning module** (all routes guarded; DTOs validated with `class-validator`; Swagger documented):
   - `POST /episodes` -> validates, calls Python `POST /episodes`, then inserts `(learner, episode_id)` in `app.learner_episode`; if the insert fails, return 500 with a safe message (the unowned Python episode is unreachable).
   - `GET /episodes` -> the learner's episodes (id, status, day, length, created) built from `app.learner_episode` plus Python public state; never kind (for mixed) or identity.
   - `GET /episodes/:id`, `GET /episodes/:id/bars`, `POST /episodes/:id/advance`, `GET|POST /episodes/:id/predictions`, `GET /episodes/:id/score`, `POST /episodes/:id/reveal`.
   - `GET /me/progress` -> calls Python `POST /learning/summary` with the ids the learner owns (never all).
2. **Ownership guard:** every `:id` route first checks `(learner, episode)` in `app.learner_episode`; missing pair -> **404** with the same body as an unknown id.
3. **Validation before forwarding** (mirrors Python's limits): `kind` in {mixed, real, synthetic}; `n_bars` 60 to 500; `initial_visible` 20 to `n_bars - 1`; advance `n` 1 to 20; `horizon` in {1, 5, 10}; `p_up` in [0.01, 0.99] with at most 4 decimals; bodies with unknown fields are rejected (whitelist + forbid non-whitelisted). Invalid input answers 422 **without any call to Python**.
4. **Response whitelisting (defence in depth):** before the reveal, responses are rebuilt from an explicit list of allowed fields (`day`, `open`, `high`, `low`, `close`, `rel_volume`, counts, statuses, scores, warnings); an unexpected upstream field such as `symbol` is dropped and a warning is logged without its value. After the reveal the identity block is passed through with its own whitelist.
5. **Error mapping:** upstream timeout -> 504, upstream 5xx -> 502, upstream 409 -> 409, upstream 404 -> 404, each with a short plain-language message and the `x-request-id`.
6. **Glossary as data:** migration creating `app.glossary_term(slug text PK, term text, plain_definition text, example text, level text, category text, related text[], source text)`; a seed script `npm run seed:glossary` that (a) imports the rows of `docs/02-domain/glossary.md` and (b) overlays beginner wording from `apps/api/seed/learning-terms.json` for the terms the screens use (close, open, high, low, candle, day, horizon, probability, prediction, Brier score, coin flip, calibration, base rate, luck, blind, reveal, synthetic, sample size, overconfidence, hindsight, lineage). Each learning term has a one-to-three sentence definition in plain language and an example with numbers. Routes `GET /glossary?q=&category=` and `GET /glossary/:slug` (public, no login).
7. **Request trace:** a middleware assigns `x-request-id`, and an in-memory ring buffer (last 200 entries, per learner id) stores `{request_id, time, method, route pattern, status, duration_ms, upstream: [{service, route pattern, status, duration_ms}]}`. Route patterns, not concrete ids and never bodies, headers or tokens. `GET /trace?limit=` (guarded) returns the caller's last entries only. Also `GET /system` (guarded): the gateway, Python and database status as in `/health`, the latest `app.pgmigrations` name and the Python Alembic head read from `market.alembic_version` (read-only, allowed: a service may read another's schema), and the ownership table (which service owns which schema).
8. Refresh `docs/02-domain/openapi-gateway.json`; the contract test must pass.

## Where to do it
- Folder / file: `apps/api/src/learning/`, `src/glossary/`, `src/trace/`, `src/system/`, `apps/api/seed/learning-terms.json`, `apps/api/migrations/`.
- Technology: NestJS, `class-validator`, `pg`, Vitest + Supertest, an HTTP mock for Python.
- Database schema/ownership: `app.glossary_term` (new), reads `app.learner_episode`; reads `market.alembic_version` only.

## Inputs
- 06_05 endpoints (mocked in unit tests; one real end-to-end run in 06_12); `docs/02-domain/glossary.md`.

## Deliverables
- Learning, glossary, trace and system modules, migration, seed, tests, refreshed OpenAPI.

## Acceptance criteria / tests
- [ ] **Isolation fuzz (negative):** two learners A and B, 100 random cross-access attempts (every `:id` route, both directions, random ids) return 404 (or 401 without a token) and make **zero** calls to Python; the owner's calls return 200.
- [ ] Validation: each invalid input of step 3 returns 422 and the mocked Python receives zero calls (assert call count).
- [ ] Whitelisting: a mocked Python reply that adds `symbol`, `name` and `start_date` to a pre-reveal response is not forwarded (assert absent from the gateway response); after `reveal` the identity block appears.
- [ ] Error mapping: mocked timeout -> 504, 500 -> 502, 409 -> 409, with safe messages that do not contain the upstream URL, token or body.
- [ ] `GET /me/progress` for A counts only A's episodes (B has other predictions).
- [ ] Glossary: seed is idempotent (second run changes nothing); search `?q=brier` finds the Brier score; every term used by the learning screens exists (test compares against a list in `learning-terms.json`); each learning definition has at most 40 words and a reading-ease score of at least 60 (script from 06_08 or an equivalent check here).
- [ ] Trace: entries contain route patterns only (no ids, no query values, no bodies, no `Authorization`); learner A never sees B's entries (negative); the buffer never holds more than 200 entries.
- [ ] `GET /system` returns statuses and versions, and its ownership table lists `app -> NestJS`, `market, research -> Python`.
- [ ] Migration up/down/up for the glossary table; contract test passes; renaming a DTO field is detected.
- [ ] Standing invariants: replay boundary (the gateway adds no path that reads beyond the cursor: all bar reads go through the Python endpoint), idempotency (double `POST /predictions` returns the same record), reconciliation (`/me/progress` counts add up).

## Out of scope
- Lessons and quizzes, trade journal, leaderboards, deleting episodes, WebSockets.

## Notes for the implementer
Keep controllers thin: validate, check ownership, call the client, map the answer. If you find yourself computing a number in NestJS, stop: it belongs in Python.
