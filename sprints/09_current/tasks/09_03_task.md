# Task 09_03: Paper decisions in Python: record a stance, mark it to market without leakage

**Sprint:** 09     **Depends on:** 09_02     **Size:** L
**Concepts to read first:** [09_02](../concepts/09_02_paper-trading-without-future-leakage-recording-a-decision-before-the-outcome.md), [09_06](../concepts/09_06_append-only-records-and-reconciling-a-ledger.md)

## Goal
A learner's stance (long or flat) on an episode day can be recorded once, never edited, and its result is computed only from the days the replay has reached.

## Context
Blueprint MVP items 7 and 9 (record a simulated decision; see trade-level results). Python owns schema `research`; the gateway will own who may call it.

## What to do
1. Migration `0013`: `research.paper_decision(decision_id identity PK, episode_id FK, day int, stance text check in ('long','flat'), reason text (at most 280 characters), client_key text, cost_bps real, created_at)` with UNIQUE (episode_id, client_key) and a trigger that forbids UPDATE and DELETE (append-only enforced in the schema).
2. `market_data/learning/paper.py`: `record_decision` (day must equal the episode's current day; a repeated client key returns the stored row, `created=false`), `mark_to_market` (a long stance earns the next revealed day's change; a change of stance pays cost_bps; only days up to the current day are used), `journal(episode_id)` with per-decision result status (`pending` until the next day is revealed) and totals.
3. Router `Paper`: `POST /episodes/{id}/decisions`, `GET /episodes/{id}/decisions`; caps (reason length, 250 decisions per episode, cost 0 to 50 bps); no date, symbol or kind in replies before the reveal.
4. Tests: schema trigger refuses update and delete; idempotent client key; result of a decision on day t is `pending` until day t+1 exists; results use only revealed days (truncation-style test); costs charged on stance change only; totals equal the sum of rows (reconciliation); leak scan of every reply for an open mixed episode.
5. Swagger for all functions; refresh the contract.

## Where to do it
`migrations/versions/0013_*.py`, `learning/paper.py`, `api/routers/paper.py`, `tests/learning/test_paper.py`.

## Inputs
The Learning module's episode state and bars.

## Deliverables
Migration, module, router, tests, OpenAPI.

## Acceptance criteria / tests
- [ ] Migration up, down, up; the trigger rejects UPDATE and DELETE (negative).
- [ ] Same client key twice stores one row.
- [ ] A decision for a day other than the current one is refused with 422.
- [ ] No reply of an open episode contains a date, symbol or episode kind (leak scan; planted leak detected).
- [ ] Recomputing every result from the rows equals the stored totals.
- [ ] Standing invariants: idempotency, replay boundary, reconciliation.

## Out of scope
Position sizing, leverage, shorting, stop orders, multi-symbol portfolios.

## Notes for the implementer
A paper decision is a stance, not advice. Never call a result a score.
