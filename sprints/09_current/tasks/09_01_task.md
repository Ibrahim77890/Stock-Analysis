# Task 09_01: Person-run walkthrough, screen-reader pass and fixes (carried over from 08_01)

**Sprint:** 09     **Depends on:** none     **Size:** M
**Concepts to read first:** [09_05](../concepts/09_05_accessible-tabs-toggles-and-secondary-chart-panels.md)

## Goal
One person who did not build MarketLab has followed the learning walkthrough, one lesson and the Lab steps, someone has listened to the key screens with NVDA, and every hesitation is fixed or listed.

## Context
Open since Sprint 06 (`sprints/08_done/pending/08_P01`). The path, lessons and demos added in Sprint 08 also need a stranger's eyes before more is built on top.

## What to do
1. Ask one person who has never seen the app to follow `docs/02-domain/learning-walkthrough.md`, then lesson 2 of the path and the Lab steps, with no help. Observe and write; do not guide.
2. Record per step: pass or fail, time, what the person said or did when stuck, words not understood, in a new section of the walkthrough document.
3. Install NVDA (free) and listen to sign-in, an episode, the score screen, a Lab result and a lesson page; write what was read out and what was confusing.
4. Turn every hesitation into a fix (copy, markup, label, glossary term) or a `pending/` item with a reason; re-run copy tests, web tests and all five `npm run walk` modes after each fix.

## Where to do it
`docs/02-domain/learning-walkthrough.md`, `apps/web/src/**`.

## Inputs
The running stack, a willing person, NVDA.

## Deliverables
Filled-in sections, fixes, pending items, completion note.

## Acceptance criteria / tests
- [ ] Every walkthrough, lesson and Lab step has a recorded result.
- [ ] The screen-reader section says who listened to which screens; if no screen reader was used the task is marked partial.
- [ ] After the fixes all web tests and walk modes pass.
- [ ] One fix is shown to be needed by a test or script that failed before it.

## Out of scope
New lessons, redesign beyond the fixes.

## Notes for the implementer
If no person is available do not mark this done; leave it in `pending/` and finish the rest of the sprint.
