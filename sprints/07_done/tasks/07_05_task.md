# Task 07_05: Lab foundation in the web app: pick a stock, start a study, write a rule

**Sprint:** 07     **Depends on:** 07_04     **Size:** M
**Concepts to read first:** [07_01](../concepts/07_01_what-a-backtest-shows-and-what-it-does-not.md), [07_06](../concepts/07_06_explaining-performance-numbers-and-charts-to-beginners.md)

## Goal
A beginner can open the Lab, choose a stock, start a study, and describe a simple rule ("buy when the short average rises above the long average") in a form that explains every box, before any result exists.

## Context
Blueprint Section 24 (web client is a thin view over the gateway) and Sprint 06 design rules (light only, plain words, glossary on every new term, contrast and reading-ease tests). The Lab is a new area next to Learn and Score.

## What to do
1. Regenerate `apps/web/src/api/schema.d.ts` from `docs/02-domain/openapi-gateway.json`; add typed client functions for the six Lab routes in `src/api/client.ts` (the token and error handling already exist).
2. Add pages under `src/lab/` and routes `/lab`, `/lab/:studyId`; add "Lab" to the navigation. Pages: **Lab home** (short "what this is and is not" paragraph, list of the learner's studies with symbol, ideas tried, vault opened yes/no, and a "Start a study" button) and **Study page** (shell with a rule form and, below, the area where 07_06 puts results).
3. **Start a study:** a stock picker (search by symbol or name, from `GET /lab/stocks`, showing years of data in words), a one-paragraph explanation of the vault ("part of the history is locked away and can be opened only once"), a button "Start study". Errors (cap of 20, unknown stock) use the plain messages from the gateway.
4. **Rule form** (fast and slow average lengths, cost): number inputs with visible labels, plain help text, sensible defaults (20 and 100 days, 2 basis points described as "about 0.02% per trade"), inline validation matching the caps (fast at least 2 and below slow, slow at most 300, cost 0 to 50), and a "Run on practice years" button that stays disabled while a run is in progress. A "What is a moving average?" link opens the glossary term.
5. Add copy in `src/copy/lab.ts` (checked by the copy tests: reading ease 60 or more, sentences up to 25 words, no words from the banned list: "beats the market", "edge", "profit", "alpha", "guarantee"). Add the new beginner terms to `apps/api/seed/learning-terms.json` and re-seed: moving average, crossover, practice years, vault, basis point, buy and hold, trial/idea tried, overfitting. Each with a one-sentence definition, an example and a "why it matters"; update `docs/02-domain/glossary.md`.
6. Extend the guided tour with a short Lab step (3 stops at most), shown once and re-openable from the help button.
7. Component tests: the picker filters and selects, the form blocks invalid input with a message beside the field, the button is disabled during a run, every new term in copy resolves to a glossary entry (existing test extended).

## Where to do it
- Folder / file: `apps/web/src/lab/`, `src/copy/lab.ts`, `src/api/`, `src/components/Layout.tsx`, `apps/api/seed/learning-terms.json`, `docs/02-domain/glossary.md`.
- Technology: React, TypeScript, Vitest + Testing Library (jsdom), existing tokens.
- Database schema/ownership: none in the browser.

## Inputs
- Gateway Lab routes (mocked in component tests, real in 07_08).

## Deliverables
- Lab home, start flow, rule form, copy, glossary additions, tour step, tests.

## Acceptance criteria / tests
- [ ] The Lab home lists studies and the start flow creates one through the mocked gateway; the cap error from the gateway is shown as plain text in the page (not in a console only).
- [ ] The form refuses `fast >= slow`, `slow = 301`, `cost = 51`, empty and non-numeric input with a message next to the field; a valid form sends exactly the typed numbers; no request is sent for an invalid form (negative tests).
- [ ] Copy tests pass for `lab.ts` (reading ease, sentence length, banned words); the banned-word test fails if "edge" is added (negative test).
- [ ] Every `{{slug|label}}` in the new copy resolves to a seeded term; the glossary count in the docs matches the database after re-seeding.
- [ ] Contrast tests still pass; the new components use tokens only (a test greps for hard-coded colours in `src/lab`).
- [ ] All inputs have visible labels and are reachable and operable by keyboard (checked in 07_08 with the browser walk; here a component test tabs through the form).
- [ ] All existing web tests still pass.
- [ ] Standing invariants: reconciliation (the study list count equals the gateway's list), idempotency (double click on "Start study" creates one study).

## Out of scope
- Results display (07_06), vault flow (07_07), other rules, saving drafts.

## Notes for the implementer
Do not show any number, example result or "typical" performance on this screen: nothing should suggest a good setting before the learner tries one.
