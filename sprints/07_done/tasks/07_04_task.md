# Task 07_04: Gateway lab module: studies per learner, validation, rate limit, whitelist

**Sprint:** 07     **Depends on:** 07_03     **Size:** L
**Concepts to read first:** [07_05](../concepts/07_05_protecting-expensive-endpoints.md), [07_02](../concepts/07_02_trying-many-ideas-overfitting-and-the-number-of-tries.md), [07_03](../concepts/07_03_the-vault-out-of-sample-holdout-and-one-use-tests.md)

## Goal
A signed-in learner can create and use their own lab studies through the gateway; nobody can see or run another learner's study; every request is validated and rate-limited; vault information cannot reach the browser before the vault is opened.

## Context
Blueprint Section 24 (the gateway owns users, ownership and progress; it computes nothing) and ADR 0014 (404 for others' objects, whitelisting, safe errors). The Sprint 06 learning module is the pattern.

## What to do
1. Migration (node-pg-migrate, schema `app`): `app.learner_study(learner_id uuid FK -> app.learner ON DELETE CASCADE, study_id bigint NOT NULL, symbol text NOT NULL, created_at timestamptz DEFAULT now(), PRIMARY KEY (learner_id, study_id), UNIQUE (study_id))`. Up and down.
2. Module `src/lab` with guarded routes: `GET /lab/stocks`, `POST /lab/studies`, `GET /lab/studies`, `GET /lab/studies/:id`, `POST /lab/studies/:id/runs`, `POST /lab/studies/:id/vault`. Ownership check on every `:id` route (404 for another learner's id and for an unknown id, same body, no call to Python). At most 20 studies per learner (422 with a plain message).
3. DTOs with `class-validator` mirroring the Python caps (`2 <= fast < slow <= 300`, `0 <= cost_bps <= 50`, `seed` optional 0 to 2,147,483,647); the vault route requires `confirm: true` and the exact `fast`, `slow`, `cost_bps` (so a double click or a stray request cannot open it); unknown fields rejected.
4. **Rate limit:** at most 20 runs per minute per learner (configurable `LAB_RUNS_PER_MINUTE`), answered with 429 and the `Retry-After` header and a plain message; the vault route is limited to 3 calls per minute. The limiter is separate from the login limiter.
5. **Whitelisting:** every response is rebuilt from field lists (as in 06_07); before the vault is opened, any field whose name or value looks like a date after the practice end is impossible by construction (the lists contain no date fields except yearly table labels that are years inside practice). A leaked vault field from a fake Python is dropped and logged by name.
6. Error mapping: Python 422 -> 422 with its plain message, 409 -> 409, 504/502 as in Sprint 06; timeouts 30 s for runs.
7. Extend the request trace sentence map data (route patterns for the new endpoints) and `GET /system` unchanged.
8. Regenerate `docs/02-domain/openapi-gateway.json` and add response DTOs for the web types.

## Where to do it
- Folder / file: `apps/api/migrations/`, `apps/api/src/lab/`, `apps/api/src/python/python-client.ts`, `apps/api/test/lab.spec.ts`.
- Technology: NestJS, `class-validator`, `pg`, Vitest + Supertest.
- Database schema/ownership: `app.learner_study` (gateway); Python tables only through Python.

## Inputs
- 07_03 endpoints (mocked in unit tests); the Sprint 06 gateway.

## Deliverables
- Migration, lab module, rate limiter, DTOs, tests, refreshed OpenAPI.

## Acceptance criteria / tests
- [ ] Migration up/down/up for `app`; the Python tables are untouched.
- [ ] **Isolation fuzz (negative):** two learners, 100 random cross-access attempts on every study route all give 404 (401 without a token) with identical bodies and **zero** Python calls; owners get 200.
- [ ] Validation: each invalid input of step 3 (including `slow = 301`, `fast >= slow`, `cost_bps = 51`, an extra field, a vault call without `confirm`) returns 422 with zero Python calls.
- [ ] Rate limit: the 21st run in a minute returns 429 with `Retry-After`; the counter is per learner (another learner is unaffected); the vault route's 4th call in a minute returns 429.
- [ ] Idempotent repeat: two identical run requests return the same numbers and `counted = false` the second time (fake Python records one trial).
- [ ] Whitelisting: a fake Python that adds `practice_end`, `vault_start`, a vault metric and a date inside the yearly table to a pre-vault reply: none reach the learner (assert absent); after the vault call the vault block appears.
- [ ] A study cap: the 21st study returns 422; deleting nothing changes the count.
- [ ] Safe errors: mocked 504/502 give plain messages without URLs, tokens or "upstream".
- [ ] Contract test passes and detects a renamed DTO field; `npm run check:python-api` passes.
- [ ] Standing invariants: replay boundary (no vault data before the vault call), idempotency (repeat run), reconciliation (study counts per learner match `app.learner_study`).

## Out of scope
- The web pages (07_05 to 07_07), notifications, deleting studies, sharing studies between learners.

## Notes for the implementer
Do not compute a percentile, a Sharpe or a trial count in NestJS; forward what Python returns. If a validation rule is missing in Python, add it there first.
