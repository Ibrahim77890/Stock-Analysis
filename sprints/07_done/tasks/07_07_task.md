# Task 07_07: Lab vault flow in the web app: open the vault once, compare practice and vault

**Sprint:** 07     **Depends on:** 07_06     **Size:** M
**Concepts to read first:** [07_03](../concepts/07_03_the-vault-out-of-sample-holdout-and-one-use-tests.md), [07_06](../concepts/07_06_explaining-performance-numbers-and-charts-to-beginners.md)

## Goal
The learner can spend the single vault opening on the rule they choose, after a clear confirmation, and then sees practice and vault results side by side with an honest reading of the gap.

## Context
Sprints 04 and 07_02 give one use per study. The lesson is felt only if the interface makes the one-use rule obvious and makes it hard to open by accident.

## What to do
1. **Vault card** on the study page: state before opening ("Locked. Opens once. About N years of data you have not seen."), shown only when at least one rule has been run.
2. **Confirmation dialog** built into the page (no browser `confirm`): shows the rule's numbers (fast, slow, cost) in words, says "You can do this only once for this study. Whatever you see, you cannot try again with this stock in this study.", requires typing the word `OPEN` (or ticking an explicit box and pressing the button), has "Cancel" focused first, closes on Escape, and returns focus to the vault card. The submit button is disabled until the confirmation is complete and while the request is in flight (double click sends one request).
3. **After opening:** a side-by-side view of practice and vault for the same rule and for buy and hold (return, worst fall, trades), a growth-of-100 chart for the vault years only (log scale, same style), and a written reading generated by fixed rules from the numbers (for example: vault return lower than practice return by more than 5 percentage points -> "The rule did much worse on years it had not seen. That is common after trying many ideas."), never a verdict on the rule.
4. **Trial-count line:** "You tried N ideas before opening the vault." with the overfitting meter value from the practice run.
5. After opening, the vault card shows the result permanently (reload-safe) and the run form is disabled for new vault use; further practice runs stay possible and say they no longer protect the vault.
6. Errors: 409 (already opened elsewhere, for instance in another tab) shows the saved vault result instead of an error; 429, 504, 422 show plain messages and leave the vault unopened where the server says so.
7. Copy in `src/copy/lab.ts` (extended), checked by the same tests.
8. Component tests with fixtures: locked state, dialog flow (cancel, escape, wrong word, correct word), double click sends one request, opened state, 409 path, reading-sentence rules (three fixtures: much worse, similar, better).

## Where to do it
- Folder / file: `apps/web/src/lab/vault/*`, `src/copy/lab.ts`, `apps/web/test/lab-vault.test.tsx`.
- Technology: React, Lightweight Charts, Vitest + Testing Library.
- Database schema/ownership: none.

## Inputs
- Gateway vault route (07_04), fixtures from a real vault call on a test database.

## Deliverables
- Vault components, dialog, reading rules, copy, tests.

## Acceptance criteria / tests
- [ ] The dialog cannot be confirmed without the explicit step (wrong word, empty, cancel, Escape each send zero requests: negative tests).
- [ ] Double click and Enter pressed twice send exactly one vault request.
- [ ] Focus is trapped in the dialog while open, starts on Cancel and returns to the vault card on close (component test with `userEvent`).
- [ ] Before opening, no vault date, dates or metric is rendered anywhere on the page (test scans the document text of the locked state).
- [ ] The reading sentence matches the rule table for the three fixtures and never contains a banned word.
- [ ] The 409 path shows the saved result without an error banner.
- [ ] After opening, the run form still works for practice and the page says that new practice runs no longer protect the vault.
- [ ] Contrast, reading-ease and sentence-length tests pass.
- [ ] Standing invariants: idempotency (one request per confirmation), replay boundary (no vault content before opening), reconciliation (practice numbers in the side-by-side view equal the run list entry).

## Out of scope
- A second vault, resetting a study, comparing several rules on the vault.

## Notes for the implementer
Do not soften the one-use rule with a "reset" for convenience. If a learner wants another go, they start a new study on another stock; say so in the copy.
