# Task 03_07: Luck control (bootstrap and random-walk shuffle test)

**Sprint:** 03     **Depends on:** 03_03     **Size:** M
**Concepts to read first:** [03_05](../concepts/03_05_luck-controls-shuffle-and-bootstrap.md), [03_02](../concepts/03_02_moving-average-crossover.md), [03_04](../concepts/03_04_performance-metrics.md)

## Goal
For any backtest spec, the system can run the same strategy on seeded synthetic paths built from the real bars and report how the real result ranks among them.

## Context
Blueprint 23.2 "Luck control (shuffle test)". This is the first tool that turns "it made money" into "how unusual is that?".

## What to do
1. Implement `bootstrap_paths(bars, n, block_length, seed)`: from "bar relatives" (open/prev close, high/open, low/open, close/open) draw blocks with replacement and rebuild OHLCV bars from the first close; volume resampled with its bar.
2. Implement `gbm_paths(bars, n, seed)`: independent normal log returns with the real series' mean and sample std; build OHLC with the same relatives sampled independently per bar.
3. Implement `shuffle_test(bars, spec, method, n_paths=200, block_length=20, seed=1)`: runs `run_backtest` on each path (same costs), returns per-path total return and Sharpe, quantiles (5, 25, 50, 75, 95), the real result's percentile rank, the fraction of paths with a result >= real, and the method, seed and parameters.
4. Use one `numpy.random.default_rng(seed)` per call; derive the path RNGs by `SeedSequence.spawn` so paths differ and the run is reproducible.
5. Document in `docs/02-domain/backtest.md` what each method preserves and destroys, with the warning that the fraction is not a significance test.

## Where to do it
- Folder / file: `services/market-data/src/market_data/luck.py`, `tests/test_luck.py`, `docs/02-domain/backtest.md`.
- Technology: Python, NumPy `Generator`, Polars.

## Inputs
- Real bars (AAPL, SPY) via the engine; no new data.

## Deliverables
- `luck.py`, tests, docs section.

## Acceptance criteria / tests
- [ ] Same inputs and seed give identical output; a different seed gives different output (reproducibility).
- [ ] Every synthetic bar passes the OHLC sanity rules (high >= max(open, close), low <= min(open, close), all prices > 0) for 200 paths.
- [ ] Synthetic paths have the same number of bars as the real series and the first close equals the real first close.
- [ ] Block bootstrap with `block_length` equal to the series length reproduces the real path (sanity: bars identical to the original).
- [ ] Control with no edge: on a seeded GBM series, the real-result percentile of the SMA crossover is not extreme in 20 of 20 independent seeds, or the test records the exact proportion; choose the thresholds before running and write them in the test.
- [ ] Negative tests: `n_paths` < 1, `block_length` < 1 or longer than the series, unknown method raise `ValueError`.
- [ ] Real-data run: AAPL and SPY, default parameters, results recorded in the completion note, whatever they show.
- [ ] Standing invariant: reproducibility.

## Benchmark (when relevant)
- Informational: seconds for 200 paths on one 6-year series; record machine. No target.

## Out of scope
- Stationary bootstrap, volatility-clustering models (GARCH), p-value correction for many parameters.

## Notes for the implementer
Report honestly if the bootstrap keeps strong drift and a buy-signal strategy looks good on it; that is exactly the lesson.
