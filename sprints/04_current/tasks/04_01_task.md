# Task 04_01: Validation protocol, data-window audit and the trial registry

**Sprint:** 04     **Depends on:** none     **Size:** M
**Concepts to read first:** [04_01](../concepts/04_01_overfitting-and-multiple-testing.md), [04_02](../concepts/04_02_in-sample-out-of-sample-embargo-and-holdout.md)

## Goal
The rules of honest validation (what counts as a trial, how data are split, when the holdout may be used) are written in an ADR, the real data window of every symbol is documented, and the database has empty `study` and `trial` tables ready to record searches.

## Context
Blueprint 26.4 item 7 and 23.2 "Overfitting meter". Sprint 03 lesson: check the real data window before writing windows into specs (most symbols have only 1,366 bars from 2020-07-27, so splits must be small).

## What to do
1. List, per symbol in `market.instrument`, the first date, last date and number of stored bars (use `read.list_instruments` or `bar_range_stats`; do not query `market.bar_daily` directly).
2. Write the table into `docs/02-domain/data-profile-v1.md` as a new section "Bars per symbol (Sprint 04 audit)" and state how many symbols have at least 1,000 bars.
3. Write ADR `docs/04-adr/0012-validation-protocol.md`: definition of study and trial; train, test and holdout rules; embargo default (5 bars); warm-up rule (past bars may feed indicators); one-use holdout; what the registry cannot count (ideas tried elsewhere); the minimum window for a split (state a number and why, based on the audit).
4. Create migration `0008` (`uv run poe migration-new create study and trial tables`): `research.study(study_id bigint identity PK, name text, family text, symbol text, created_at timestamptz default now(), holdout_used_at timestamptz NULL)` and `research.trial(trial_id bigint identity PK, study_id FK ON DELETE CASCADE, phase text CHECK in ('train','test','holdout'), params jsonb, window_start date, window_end date, config_hash text, total_return double precision, sharpe double precision, trades integer, created_at timestamptz default now())`.
5. Run migration up, down, up and compare `\dt research.*` each time.
6. Add both tables to `docs/02-domain/data-dictionary.md`.

## Where to do it
- Folder / file: `docs/04-adr/0012-validation-protocol.md`, `services/market-data/migrations/versions/0008_*.py`, `docs/02-domain/data-profile-v1.md`, `docs/02-domain/data-dictionary.md`.
- Technology: Alembic hand-written SQL via `op.execute`, existing `read.py` functions.
- Database schema/ownership: `research` (Python service). `market` is not modified.

## Inputs
- Sprint 03 outputs; loaded Alpaca bars (53 symbols).

## Deliverables
- Audit table, ADR 0012, migration 0008, data dictionary rows.

## Acceptance criteria / tests
- [ ] `uv run poe migration-heads` shows one head `0008`; up/down/up leaves identical `\dt research.*`; the down step removes only the two new tables.
- [ ] The audit table has one row per symbol (53) and its counts equal `read.list_instruments` output (a test compares them).
- [ ] Negative test: inserting a trial with phase `other` is rejected by the CHECK constraint; inserting a trial for a missing study is rejected.
- [ ] The ADR states the one-use holdout rule and the effect of a second look.
- [ ] Standing invariant: the `market` schema is unchanged (`\dt market.*` identical before and after).

## Out of scope
- Any search or split code (04_02 onward); a UI.

## Notes for the implementer
Use fixed wording for phases: `train`, `test`, `holdout`. Keep the ADR short; the point is that someone else can check the code against it.
