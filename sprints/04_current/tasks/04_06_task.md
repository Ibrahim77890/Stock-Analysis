# Task 04_06: Universe scan and the best-of-N control

**Sprint:** 04     **Depends on:** 04_05     **Size:** M
**Concepts to read first:** [04_05](../concepts/04_05_selection-bias-best-of-n-and-survivorship.md), [04_04](../concepts/04_04_sharpe-uncertainty-psr-and-dsr.md)

## Goal
The same strategy can be run over every eligible symbol in the database, and the best symbol's Sharpe is compared with the best of N simulated random-walk symbols, with an explicit universe caveat.

## Context
Blueprint 23.3 item 3 (survivorship) and 23.2 (luck control). Choosing a symbol is a search; this task makes that visible with the data MarketLab holds.

## What to do
1. Implement `universe_scan(conn, spec_template, symbols=None, min_bars=500)`: for each eligible symbol load split-adjusted bars (`read.get_bars`), run the backtest, return rows (symbol, bars, total_return, sharpe, trades), the skipped symbols with reasons (too few bars), quantiles of Sharpe, and the count N.
2. Implement `best_of_n_control(conn, spec_template, symbols=None, replicates=100, seed=1)`: for each replicate build one GBM path per symbol (reuse `luck.gbm_path` with the symbol's own bars), run the strategy, record the maximum Sharpe across symbols; return the distribution of maxima, the real maximum's percentile rank and the fraction of replicates with a maximum at least as large.
3. Add the universe caveat text to every result (current-day symbols only; survivors; IEX data; window).
4. Show the ten symbols with the highest and lowest Sharpe in `docs/02-domain/validation.md` with the caveat.

## Where to do it
- Folder / file: `services/market-data/src/market_data/validation.py` (or a new `scan.py`; record the choice), tests in `services/market-data/tests/test_universe_scan.py`.
- Technology: Python, Polars, NumPy, psycopg 3, `luck.py`.
- Database schema/ownership: read-only on `market` through `read.py`; nothing written.

## Inputs
- 53 loaded symbols; Sprint 03 `luck.py`.

## Deliverables
- `universe_scan`, `best_of_n_control`, tests, docs section.

## Acceptance criteria / tests
- [ ] Scan of the real database returns N equal to the number of symbols with at least `min_bars` bars, and skipped symbols are listed with a reason; counts reconcile (N + skipped = symbols in the database).
- [ ] Reproducibility: same seed gives identical control output; another seed differs.
- [ ] On a synthetic universe of 30 random walks (seeded) the real maximum's rank is not extreme in at least 16 of 20 seeds (rank inside [0.025, 0.975]; threshold written before running).
- [ ] The maximum over N paths is non-decreasing when symbols are added (checked on fixed paths).
- [ ] Negative tests: unknown symbol in `symbols`, `replicates < 1`, empty eligible set raise `ValueError`; a symbol with 100 bars is skipped with a reason, not crashed on.
- [ ] Real run: record N, the best and median Sharpe, the real maximum's percentile among 100 replicates, and runtime in the completion note.
- [ ] Standing invariants: reproducibility, replay boundary (an optional `end` date is honoured, tested by comparing with a database-copy truncated at that date for one symbol).

## Benchmark (when relevant)
- Informational: seconds for the scan and for 100 replicates x 53 symbols; record the machine.

## Out of scope
- Delisted names and a survivorship demonstration (deferred; needs another dataset), sector-neutral or correlation-adjusted controls.

## Notes for the implementer
The symbols are correlated (ETFs overlap their stocks); say that the effective N is smaller than N.
