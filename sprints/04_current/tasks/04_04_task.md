# Task 04_04: Walk-forward analysis

**Sprint:** 04     **Depends on:** 04_03     **Size:** M
**Concepts to read first:** [04_03](../concepts/04_03_walk-forward-analysis.md), [04_02](../concepts/04_02_in-sample-out-of-sample-embargo-and-holdout.md)

## Goal
A rolling walk-forward run selects parameters on each training window, trades the following block, and returns per-fold results, parameter stability and one stitched out-of-sample equity curve with its metrics.

## Context
Blueprint 26.4 item 7. One split is one draw; several folds show whether the selection is stable.

## What to do
1. Implement `make_folds(n_bars, train, test, embargo)` returning train and test index ranges for each full fold (rolling window, step = test length); reject non-positive sizes and windows that fit no fold.
2. Implement `walk_forward(bars, base_spec, grid, train, test, embargo=5, metric="sharpe")` using `evaluate_split`-style logic per fold (selection on the fold's train window only; test block with `slow` warm-up bars, starting flat).
3. Stitch the test blocks: each block's equity is rebased to 1 at its start and blocks are chained by growth factor; compute metrics on the stitched curve through `metrics.summarise`-compatible inputs.
4. Return per fold: ranges, selected pair, IS Sharpe, OOS Sharpe, OOS return, OOS trades; plus `parameter_changes` (count of folds whose pair differs from the previous one) and the stitched metrics.
5. Record every fold's train trials and test evaluation in a new study.
6. Describe the method and its simplifications (each fold starts flat, no overlapping positions) in `docs/02-domain/validation.md`.

## Where to do it
- Folder / file: `services/market-data/src/market_data/validation.py`, tests in `services/market-data/tests/test_walk_forward.py`.
- Technology: Python, Polars, psycopg 3.
- Database schema/ownership: `research.study`, `research.trial` (write).

## Inputs
- 04_03 functions; SPY and AAPL bars; seeded synthetic bars.

## Deliverables
- `make_folds`, `walk_forward`, tests, docs section.

## Acceptance criteria / tests
- [ ] With 1,366 bars, train 500, test 100, embargo 5, `make_folds` returns exactly 8 folds; first test starts at index 505 (0-based) and the last test ends at index 1,304.
- [ ] Property test (100 random sizes): within each fold train and test never overlap, the embargo gap is respected, and test blocks never overlap each other.
- [ ] Leakage test: changing any bar after a fold's train end does not change that fold's selected pair (checked for every fold).
- [ ] Stitching: the stitched growth factor equals the product of the folds' growth factors within 1e-9 (reconciliation).
- [ ] Negative tests: `train + embargo + test` larger than the frame, `test < 1`, `embargo < 0` raise `ValueError`.
- [ ] Real data: SPY with a 5 x 5 grid, train 500, test 100; per-fold table, parameter changes and stitched metrics recorded in the completion note.
- [ ] Standing invariants: causality, reproducibility (same inputs give identical output), reconciliation.

## Benchmark (when relevant)
- Informational: seconds for 8 folds x 25 pairs; record the machine.

## Out of scope
- Anchored windows, parameter smoothing, positions carried across folds.

## Notes for the implementer
Report parameter instability plainly; an unstable selection is a finding, not a failure.
