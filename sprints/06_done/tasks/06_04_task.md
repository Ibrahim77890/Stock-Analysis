# Task 06_04: Scoring functions: Brier, calibration, decomposition and the permutation luck check

**Sprint:** 06     **Depends on:** none     **Size:** M
**Concepts to read first:** [06_02](../concepts/06_02_probability-forecasts-proper-scoring-and-brier-score.md), [06_03](../concepts/06_03_calibration-reliability-diagrams-and-sample-size.md), [06_04](../concepts/06_04_overconfidence-luck-and-the-permutation-check.md)

## Goal
A pure, tested module turns a list of `(probability, outcome, horizon)` triples into the Brier score, skill score, log loss, calibration bins with Wilson intervals, the Murphy decomposition, baselines and a seeded permutation luck probability, with explicit "too few predictions" handling.

## Context
Blueprint 23.2 (prediction scoring with Brier score and calibration curve) and 23.1 (teach distrust). All numbers shown to the learner come from this module; the browser computes nothing.

## What to do
1. Create `src/market_data/scoring.py` (no database, no I/O) with:
   - `validate(forecasts, outcomes)`: equal lengths, `p` in [0.01, 0.99], `y` in {0, 1}; `ValueError` otherwise (empty input is allowed and yields `n = 0` results).
   - `brier`, `log_loss`, `skill_score(bs, reference=0.25)`.
   - `calibration_bins(forecasts, outcomes, width=0.1)`: ten bins `[0, 0.1) ... [0.9, 1.0]` (the last one includes 1.0); per bin `n`, `mean_forecast`, `observed`, `wilson_low`, `wilson_high` (95%, z = 1.96), `sparse = n < 5`; empty bins have `n = 0` and null statistics.
   - `murphy_decomposition(forecasts, outcomes, width=0.1)`: `rel`, `res`, `unc`, `brier`, and `exact` (true only when every forecast equals its bin mean).
   - `baselines(outcomes)`: coin flip (0.25) and the constant forecast `ybar` (Brier `ybar (1 - ybar)`, marked "in-sample: flattering").
   - `permutation_luck(forecasts, outcomes, horizons, n_perm=5000, seed=1)`: shuffles outcomes **within each horizon group**, returns the real Brier, the 5th/50th/95th percentiles of shuffled Briers, the count of shuffles scoring `<=` the real score, and `luck_probability = (1 + count) / (n_perm + 1)`; deterministic for a seed.
   - `summarise(...)`: one dict with `n`, all of the above, `enough = n >= 30`, and `warnings` (a list of strings): "too few resolved predictions to say anything" when `n < 30`; "overlapping horizons: effective sample is smaller than n" when any horizon above 1 is present; "sparse bins" when any non-empty bin has `n < 5`. When `enough` is false, `luck_probability` is still returned but flagged `not_reported`.
2. Write `docs/02-domain/scoring.md` with the formulas, the tie rule, the clipping, the 30-prediction rule and the limits (dependence, in-sample baseline).
3. Add one reference check against scikit-learn's `brier_score_loss` **only inside a test** (use `pytest.importorskip`; do not add scikit-learn as a runtime dependency).

## Acceptance criteria / tests
- [ ] Golden: forecasts `[0.9, 0.8, 0.3, 0.6]`, outcomes `[1, 0, 0, 1]` give Brier 0.225, skill score 0.10, log loss equal to the hand value `-(ln 0.9 + ln 0.2 + ln 0.7 + ln 0.6) / 4`.
- [ ] All forecasts 0.5: Brier exactly 0.25, `rel = (0.5 - ybar)^2`, `res = 0`, `unc = ybar (1 - ybar)`.
- [ ] Murphy identity `rel - res + unc == brier` to 1e-12 when forecasts are constant inside bins (`exact = true`), and `exact = false` otherwise.
- [ ] Wilson interval: 5 of 10 gives about [0.237, 0.763]; 0 of 5 gives about [0, 0.434]; bounds stay inside [0, 1] for 0 of n and n of n.
- [ ] Bin edges: 0.1 falls in the second bin; 0.99 in the last; 0.0999 in the first.
- [ ] Permutation: with seed 1 the result is identical on repeat; changing the seed changes the shuffle quantiles; `luck_probability` is never 0; a perfect forecaster (p = 0.99 on y = 1 and 0.01 on y = 0, n = 60) has a luck probability below 0.001; a coin-flipper's mean luck probability over 200 random datasets is within 0.05 of 0.5 (fixed seeds; Monte Carlo test).
- [ ] Negative tests: p of 0 or 1, y of 2, unequal lengths, and a NaN all raise `ValueError`; `n = 0` returns `enough = false` without raising.
- [ ] Warnings: 29 predictions -> "too few"; 30 -> not; horizon 5 present -> overlap warning; a bin with 4 points -> sparse warning.
- [ ] Property: a forecaster reporting the true probability does not score worse on average than one who exaggerates it (simulate 2,000 events with fixed seed).
- [ ] Reference check against scikit-learn `brier_score_loss` agrees to 1e-12 (skipped if scikit-learn is absent).
- [ ] Standing invariants: reproducibility (seeded), reconciliation (bin counts sum to `n`).

## Notes for the implementer
Do not report a skill statement below 30 resolved predictions; the module returns the warning, the API and the UI display it. Keep the shuffle vectorised (5,000 shuffles of a few hundred values should take well under a second).
