# Task 06_13: Documentation, fresh-database reproduction and sprint wrap-up

**Sprint:** 06     **Depends on:** 06_01 to 06_12     **Size:** M
**Concepts to read first:** [06_02](../concepts/06_02_probability-forecasts-proper-scoring-and-brier-score.md), [06_05](../concepts/06_05_precommitment-append-only-records-and-resolving-outcomes.md), [06_07](../concepts/06_07_two-backends-one-contract-nestjs-gateway-and-python-analytics.md)

## Goal
The learning loop and the three-service architecture are documented so someone else can run and judge them, everything rebuilds from scratch on an empty database, and the sprint is ready to close.

## Context
Every sprint has a documentation task (data dictionary, ADR, glossary) and a wrap-up whose last step is the completion note.

## What to do
1. ADR `docs/04-adr/0015-blind-episode-and-prediction-protocol.md`: episode state machine; what is hidden and why; the fixed rebasing scale; mixed real and synthetic episodes with the kind hidden; `made_at` set by the server; the append-only trigger; void rule; tie rule; probability bounds [0.01, 0.99]; horizons {1, 5, 10}; the 30-guess rule; ownership by the gateway; alternatives (client-side state, editable guesses, hiding only the symbol).
2. `docs/02-domain/learning-loop.md`: how a learner uses it (each screen in words), how the numbers are computed (links to `scoring.md`), what the score does and does not show, the licence limitation (Tiingo-derived charts: local machine only), and the side channels that remain (recognisable crashes).
3. `docs/02-domain/system-overview.md`: the three services, ports, schemas and who owns them, the request path, a Mermaid diagram, how to start everything (three commands), where secrets live and which are needed.
4. Data dictionary: `research.episode`, `research.prediction` (and its trigger), `app.learner`, `app.learner_episode`, `app.glossary_term`, the environment variables (names only). Glossary (`docs/02-domain/glossary.md`): at least 8 new terms (Brier score, proper scoring rule, calibration, reliability diagram, overconfidence, base rate, blind replay, precommitment, hindsight bias, permutation test, gateway) each with a source or `project definition`; re-run `npm run seed:glossary` and confirm it is idempotent.
5. READMEs: `services/market-data/README.md` (Python learning endpoints, internal token), `apps/api/README.md`, `apps/web/README.md`, and a top-level "Run MarketLab" section in the service README with the three start commands.
6. **Fresh-database reproduction** on an empty database, no network: Alembic `upgrade head` (0001 to 0011), `npm run migrate:up` (app schema), load the three sources from the local raw files, seed the glossary, run the Python learning tests, the gateway tests (including the e2e), and the web tests; confirm a seeded synthetic episode gives byte-identical blind bars and the same Brier score as recorded in the note. Also `npm ci && npm run build` from a clean `node_modules` in both apps.
7. Run the Python suite twice (with and without `TEST_DATABASE_URL`), the gateway suite and the web suite; record passed/skipped counts for each.
8. Copy the status of open items (cold-cache benchmark, Alpaca agreement PDFs, Tiingo terms-of-service document, the Alpaca duplicate-dividend rule, vendor-coded spin-offs, Playwright) into the note.
9. Write a completion note per task in `completed/`, move unfinished items to `pending/` with reasons. **Last step:** write `completed/06_13.md`.
