# Task 06_01: Architecture decision, NestJS gateway scaffold, local secrets and a typed Python client

**Sprint:** 06     **Depends on:** none     **Size:** M
**Concepts to read first:** [06_07](../concepts/06_07_two-backends-one-contract-nestjs-gateway-and-python-analytics.md), [06_06](../concepts/06_06_a-typed-frontend-over-a-typed-api.md)

## Goal
A NestJS service builds, starts and answers `GET /health` by checking itself, the database and the Python service; it has Swagger, CORS for the web app only, fails fast on missing configuration, and calls Python through a typed client. The architecture and its boundaries are written down (ADR 0014).

## Context
Blueprint Section 24: NestJS is the public gateway and owns the `app` schema; Python owns `market` and `research`. Until now only Python exists. The owner asked for NestJS in this sprint.

## What to do
1. Check `node --version` and `npm --version`. Running a NestJS app needs Node 20.19+ (this machine: 20.19.0). The `nest new` / `nest g` generators need a newer Node (see the NestJS docs); **do not depend on them**: either hand-write the project files, or, if the owner installs Node 22 LTS, say so in the note. Record the versions used.
2. Choose and create the folder (suggest `apps/api/`; record it in `sprints/current_status.md`). Hand-write: `package.json`, `tsconfig.json`, `nest-cli.json` (optional), `src/main.ts`, `src/app.module.ts`, a `health` module. Dependencies (exact versions, each at least two weeks old, `package-lock.json` committed): `@nestjs/common`, `@nestjs/core`, `@nestjs/platform-express`, `@nestjs/config`, `@nestjs/swagger`, `@nestjs/jwt`, `@nestjs/throttler`, `class-validator`, `class-transformer`, `pg`, `reflect-metadata`, `rxjs`; dev: `typescript`, `vitest`, `unplugin-swc` (decorator metadata for Vitest), `supertest`, `openapi-typescript`, `node-pg-migrate`.
3. Configuration (`@nestjs/config`, reads the repo-root `.env`): `GATEWAY_PORT` (default 3000), `DATABASE_URL`, `PYTHON_API_URL` (default `http://127.0.0.1:8000`), `INTERNAL_API_TOKEN`, `JWT_SECRET`, `CORS_ORIGINS` (default `http://127.0.0.1:5173,http://localhost:5173`). Startup validation: a missing required variable stops the process with a message that names the variable and never prints a value. Bind to `127.0.0.1` only.
4. Secrets: add placeholders `JWT_SECRET=`, `INTERNAL_API_TOKEN=` and the non-secret settings to `.env.example` with the command that generates a value (`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`). Generate real values into the git-ignored `.env` on this machine. Redact both values from every log line (reuse the idea of `config.redact` from Python).
5. `GET /health`: `{status, gateway: "ok", database: "ok"|"down", python: "ok"|"down"}`; returns 200 even when a dependency is down (the page must be able to show *which* one) but never throws; short timeouts (2 s).
6. Swagger UI at `/docs` and a script `npm run export:openapi` writing `docs/02-domain/openapi-gateway.json`; a contract test compares the committed file with the generated document (and detects a renamed field).
7. Typed Python client: `npm run gen:python-api` runs `openapi-typescript` on `docs/02-domain/openapi-market-data.json` into `src/python/schema.d.ts`; `src/python/python-client.ts` wraps `fetch` with a base URL, a timeout (5 s default, 30 s for score), the header `X-Internal-Token`, and maps failures to `UpstreamError` (status 502 for upstream 5xx, 504 for timeout, upstream 4xx passed through as the same status with a safe message). No raw upstream body is ever returned to the caller.
8. CORS: `enableCors` with the explicit origin list, methods GET/POST, headers `Content-Type, Authorization`, no credentials cookies, never `*`.
9. Write ADR `docs/04-adr/0014-gateway-and-web-stack.md`: the stack and versions; ownership rules (NestJS never computes scores, Python never handles users); request path browser -> NestJS -> Python; migrations tool for `app` (`node-pg-migrate`, SQL files, version table `app.pgmigrations`); password hashing (scrypt from `node:crypto`, OWASP parameters); tokens (JWT, signed with `JWT_SECRET`, 8 h expiry); test runner (Vitest); light theme only; licence limitation (Tiingo data are "Internal Use Only": accounts exist to separate learners on one machine, the service stays on loopback and is not deployed or shown to other people); alternatives (Next.js, Express only, Python serving the pages, a hosted auth provider).
10. Write `apps/api/README.md` (commands: `npm ci`, `npm run start`, `npm test`, `npm run gen:python-api`, `npm run export:openapi`).

## Acceptance criteria / tests
- [ ] `npm ci && npm run build && npm test` pass from a clean checkout.
- [ ] Config negative test: starting with `JWT_SECRET` unset exits non-zero and the message contains `JWT_SECRET` and not any secret value; same for `INTERNAL_API_TOKEN` and `DATABASE_URL`.
- [ ] Health test with a mocked Python: Python down gives `python: "down"` and HTTP 200; database down gives `database: "down"`.
- [ ] Python client tests (mocked HTTP): the token header is sent; a timeout becomes 504; an upstream 500 becomes 502 with a safe message and no upstream body; an upstream 404 stays 404.
- [ ] CORS: allowed origin receives the allow header with that exact origin; `https://evil.example` receives none (negative); no `*` in the configuration.
- [ ] The secrets never appear in captured logs of a full start/stop cycle (test scans the output for the values set in the test environment).
- [ ] Contract test passes; renaming a DTO field in a temporary copy is detected (negative test); `npm run gen:python-api` regenerates a file identical to the committed one.
- [ ] `git check-ignore .env` prints `.env`; the lock file is committed; `.env.example` contains no real value.
- [ ] Standing invariant: reproducibility (lock file, deterministic generation of types and OpenAPI).
