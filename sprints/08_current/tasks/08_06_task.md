# Task 08_06: Three small interactive demos inside the lessons

**Sprint:** 08     **Depends on:** 08_05     **Size:** M
**Concepts to read first:** [08_05](../concepts/08_05_explorable-explanations-small-demos-that-teach-one-idea.md), [08_01](../concepts/08_01_learning-design-for-beginners-worked-examples-retrieval-practice-and-feedback.md)

## Goal
Three seeded, keyboard-friendly demos (what 70% means, streaks in coin flips, the best of many tries) can be shown inside lesson steps and each makes one idea concrete in a few seconds.

## Context
Lesson steps may name a `demo` id (`chance-70`, `coin-streaks`, `many-tries`; schema in 08_02). Demos run in the browser on made-up data, call no server and say so; they do not describe real prices.

## What to do
1. Add `src/lessons/demos/random.ts`: a small seeded generator (mulberry32) with a unit test of its first values for seed 1 and a helper `draws(seed, n)` returning numbers in [0, 1).
2. `Chance70`: a slider (1 to 99, default 70) and a "Try another seed" button; shows 20 outcomes drawn with the seed as small up or down marks with text labels ("up", "down"), and a sentence such as "14 of 20 went up".
3. `CoinStreaks`: "Flip 100 coins" (seed shown, "Try another seed"); shows the flips as a row of H and T with the longest run marked and a sentence "The longest run was 7 heads in a row. Runs like this are normal."
4. `ManyTries`: "Try 50 random rules" on a seeded random-walk price series (made up): shows the best rule's result on the first part, then the same rule on a fresh part, with a sentence "The best of 50 did +X% on the first part and Y% on the new part." Choose the default seed so the effect is visible, document why, and offer other seeds.
5. Each demo has a one-sentence "what to look at", the words "made-up data" near the result, labelled controls, visible focus and a text result (no colour-only meaning); none calls the API.
6. Render a demo inside a lesson step when `demo` is set; unknown ids render nothing and a plain note.
7. Tests: the same seed gives the same output (all three); the text result equals the numbers drawn (count of ups, longest run, best result); sliders and buttons have accessible names; no demo imports the API client (structural test); the demo for an unknown id renders the note.

## Where to do it
- Folder / file: `apps/web/src/lessons/demos/`, `apps/web/test/demos.test.tsx`.
- Technology: React, TypeScript, Vitest; no new library.
- Database schema/ownership: none.

## Inputs
- Lesson fixtures with `demo` ids; concepts 06_04 and 07_02 for the ideas.

## Deliverables
- Three demo components, the generator, tests.

## Acceptance criteria / tests
- [ ] Determinism tests pass for each demo and a different seed gives a different result.
- [ ] The longest-run function is correct on hand-made sequences (HHTHHH gives 3; an empty sequence gives 0).
- [ ] The best-of-50 demo: on the documented default seed the first-part result of the best rule exceeds its new-part result (a regression test that the lesson's point holds for the shipped seed), and another test shows it is not true for every seed (so the page never claims it is).
- [ ] Every demo works with the keyboard only (component test with `userEvent.tab` and Enter) and the words "made-up data" appear next to each result.
- [ ] Copy tests, contrast tests and the structural "no API call" test pass.
- [ ] Standing invariants: reproducibility (seeded), idempotency (pressing the same button twice gives the same output for the same seed).

## Out of scope
- Server-side demos, real market data in a demo, animations beyond a simple redraw.

## Notes for the implementer
Say plainly that a demo is a simulation. A lucky seed must never be presented as proof.
