# Task 08_08: Documentation, fresh-database reproduction and wrap-up

**Sprint:** 08     **Depends on:** 08_01 to 08_07     **Size:** M
**Concepts to read first:** [08_04](../concepts/08_04_durable-rate-limiting-and-request-logs-in-postgresql.md)

## Goal
Everything built in Sprint 08 is documented, reproducible from an empty database, honestly summarised, and the open items are written down for the next sprint.

## Context
Every sprint ends with this task: documents must match the code, counts must be real and failures disclosed.

## What to do
1. **ADR 0018** (lessons and durable platform base): content as data and versioning; server-side answer checking and the reveal rule; no scores or ranks (why); idempotent progress; Postgres-backed limiter and trace and what was rejected (Redis, signed client-side answers, a lesson editor).
2. **Domain document** `docs/02-domain/lessons.md`: the six lessons (titles and ideas), the question rules, what progress means, how a lesson is written (schema, markers, demos), what the lessons do not claim.
3. Update `docs/02-domain/system-overview.md` (lessons data flow, durable limits), `data-dictionary.md` (`app.lesson`, `app.lesson_question`, `app.lesson_progress`, `app.quiz_answer`, `app.rate_event`, `app.request_log`), `glossary.md` if general terms were added, the three service READMEs, the root README (Path), `.env.example` if a setting was added.
4. **Fresh-database reproduction:** rebuild a scratch database from migrations (Python 0001 to 0012 and the gateway migrations), reseed glossary and lessons, run Python, gateway and web tests and the Lab fingerprint; the lesson content hash equals the real database's.
5. **Counts and honesty:** run every suite and list real counts; list skipped checks and why; list test data left in the real database.
6. **Docs-versus-code check:** extend `services/market-data/scripts/reports/docs_counts_check.py` (or a gateway script) with the lesson and migration counts; show it fails on a deliberately wrong number (negative), then restore.
7. **Completion notes** for every task in `sprints/08_current/completed/` (what was done, evidence, measured numbers, findings and fixes, what is open).
8. **Pending items** in `sprints/08_current/pending/` with reasons.
9. **Status log:** update `sprints/current_status.md` (Sprint 08 done with real numbers); do not edit other sprint folders.
10. **Repository hygiene:** secret scan of the files to share; `.gitignore` covers `data/`, `.env`, `node_modules`, `dist`; the staged list contains only allowed sprint files (`README.md`, `concepts/`, `tasks/`).
11. Report to the owner what the lessons teach, what they do not, what to try first and the open items. Offer to commit; do not commit unasked.

## Where to do it
- Folder / file: `docs/`, `README.md`, `sprints/08_current/`, `sprints/current_status.md`, `services/market-data/scripts/`.
- Technology: Markdown, existing commands.
- Database schema/ownership: a scratch database for step 4 (dropped afterwards).

## Inputs
- All earlier tasks' results.

## Deliverables
- ADR, domain document, updated docs, completion notes, pending items, status log, reproduction record.

## Acceptance criteria / tests
- [ ] ADR 0018 lists the rejected alternatives.
- [ ] The fresh-database run passes all suites and the lesson content hash equals the real database's.
- [ ] Completion notes exist for all eight tasks with real numbers and honest failures.
- [ ] `pending/` lists every unfinished item with a reason.
- [ ] Secret scan finds no key, token, password or `.env` content in shareable files.
- [ ] The docs-versus-code check passes and fails on a wrong number (negative).
- [ ] Standing invariants: reproducibility (fresh database), reconciliation (docs versus code counts).

## Out of scope
- Starting Sprint 09, deployment.

## Notes for the implementer
Say plainly what the lessons cannot do: they explain ideas and check understanding, not skill, and no one has measured whether they work.
