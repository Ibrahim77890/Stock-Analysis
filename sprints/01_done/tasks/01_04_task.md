# Task 01_04: Download raw daily bars and corporate actions with manifests

**Sprint:** 01     **Depends on:** 01_01, 01_03     **Size:** M
**Concepts to read first:** [01_03 Corporate actions](../concepts/01_03_corporate-actions-and-adjusted-prices.md), [01_04 Provenance](../concepts/01_04_data-provenance-and-licensing.md), [01_05 Idempotent ingestion](../concepts/01_05_idempotent-ingestion-and-parquet.md)

## Goal
For every universe symbol, immutable raw daily-bar files and corporate-action files exist on disk, each described by a manifest.

## Context
Blueprint 8.1 steps 1-3. The raw layer is never edited; everything downstream is derived from it.

## What to do
1. In the Python code folder create a `download` module with a function `fetch_daily_bars(symbol, start, end)` that calls the Alpaca bars endpoint with `timeframe=1Day`, `adjustment=raw`, and the feed from your sources decision; handle pagination via `next_page_token`.
2. Add bounded retry with exponential backoff for HTTP 429 and 5xx (max 5 tries); fail loudly otherwise.
3. Write each symbol's response, unmodified apart from format, to `<data>/raw/alpaca/bars_1d/<symbol>.parquet`. Never overwrite: if the file exists, write a new file with the retrieval timestamp in its name.
4. Implement `fetch_corporate_actions(symbols, start, end)` for splits and dividends; save to `<data>/raw/alpaca/corporate_actions/<year>.parquet` (or one file; your choice, record it).
5. Write a manifest JSON next to every raw file with: provider, endpoint, parameters (symbol, start, end, timeframe, adjustment, feed), retrieved_at (UTC ISO-8601), row_count, file_sha256, tool/code version, license note (copy from the Sources table).
6. Add a command-line entry point: `download --universe universe_v1.csv`, which skips symbols whose latest manifest matches the requested parameters unless `--force` is given.
7. If Alpaca access is not possible, use the fallback Kaggle dataset: download manually, place it under `<data>/raw/kaggle/`, and write manifests by hand using the same format. Note this in the status log.

## Where to do it
- Folder / file: Python code folder (module `download`), data folder (git-ignored).
- Technology: Python, httpx, Polars.

## Inputs
`universe_v1.csv`; Alpaca docs: [bars](https://docs.alpaca.markets/reference/stockbars), [corporate actions](https://docs.alpaca.markets/reference/corporateactions-1); API keys in `.env`.

## Deliverables
- Raw Parquet files for all universe symbols, and corporate-action files.
- One manifest per raw file.
- The download command and its README section.

## Acceptance criteria / tests
- [ ] Unit test with a mocked HTTP client: pagination, 429 retry, and failure after max retries.
- [ ] After a full run, the number of manifests equals the number of raw files, and each manifest's `file_sha256` matches the file (a `verify` command checks this).
- [ ] Re-running the command without `--force` makes zero API calls (test with a call counter).
- [ ] Negative test: corrupt one byte of a raw file; `verify` reports a hash mismatch.
- [ ] For every symbol, first bar date >= requested start and last <= requested end.

## Benchmark
Record total download time and rows downloaded in the status log (informational only).

## Out of scope
Intraday bars, fundamentals, SEC downloads.

## Notes for the implementer
Respect the provider's rate limits. Never print API keys to logs.
