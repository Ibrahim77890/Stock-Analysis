# Task 01_08: Data-quality rules, calendar-aware gap classification and report

**Sprint:** 01     **Depends on:** 01_07     **Size:** M
**Concepts to read first:** [01_06 Data quality](../concepts/01_06_data-quality-validation.md), [01_02 Sessions and calendars](../concepts/01_02_sessions-calendars-and-time.md), [01_03 Corporate actions](../concepts/01_03_corporate-actions-and-adjusted-prices.md)

## Goal
After a load, a quality run produces a report that says, per symbol and rule, what is wrong, with every missing trading day classified.

## Context
Blueprint 8.4 (calendars) and 8.6 (checks). Missing intervals are classified, not automatically errors; outliers are flagged, not deleted.

## What to do
1. Create a `quality` module where each rule is a small pure function returning flagged rows: `duplicate_key`, `ohlc_consistency`, `non_positive_price`, `negative_volume`, `zero_volume_day`, `large_move` (|close-to-close return| > 40%, threshold configurable), `stale_price` (identical OHLC for >= 5 consecutive sessions).
2. Add `missing_session`: expected sessions from `exchange_calendars` `XNYS` between the instrument's first and last loaded date, minus present dates.
3. Classify each missing session: `before_first_bar` / `after_last_bar` (outside the data range), `provider_gap` (inside the range), and `unknown`.
4. For `large_move` flags, check `market.corporate_action` for a split with `ex_date` within +-1 session; store `explained_by_split = true|false` in `detail`.
5. Write all results to `market.data_quality_result` with a `run_id`.
6. Generate `quality-report-<run_id>.md` (and JSON): totals per rule, per symbol, 5 example rows per rule, and the reconciliation numbers from the latest ingestion jobs.
7. Add a command `quality --run`.

## Where to do it
- Folder / file: Python code folder, module `quality`; reports in the benchmarks/docs folder you chose or a `reports/` folder (record the choice).
- Technology: Python, Polars, exchange_calendars.
- Database schema/ownership: `market.data_quality_result`.

## Inputs
Loaded tables from 01_07.

## Deliverables
- Rule functions with tests, quality run command, one saved report for the real data.

## Acceptance criteria / tests
- [ ] Unit test for each rule using a handcrafted DataFrame with at least one positive and one negative example.
- [ ] Calendar test: for 2023-11-23 (Thanksgiving) the symbol AAPL is **not** reported missing; a deliberately deleted 2023-11-21 row in a test database **is** reported as `provider_gap`.
- [ ] Split explanation test: with a synthetic 4-for-1 split (price falls ~75% on the ex-date) plus a matching `corporate_action` row, `large_move` is flagged with `explained_by_split = true`; the same drop without the corporate-action row gives `explained_by_split = false`.
- [ ] Running the quality job twice with the same data gives identical result counts (deterministic).
- [ ] No row is deleted or modified in `market.bar_daily` by the quality run (assert row count and checksum before/after).

## Benchmark
Record quality-run duration for the full universe.

## Out of scope
Fixing or imputing data; intraday checks.
