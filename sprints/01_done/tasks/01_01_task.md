# Task 01_01: Choose the repository layout and start the local environment

**Sprint:** 01     **Depends on:** none     **Size:** S
**Concepts to read first:** [01_07 Postgres schema](../concepts/01_07_postgres-time-series-schema-and-indexing.md), [01_04 Provenance](../concepts/01_04_data-provenance-and-licensing.md)

## Goal
A working local PostgreSQL, a Python environment, and a recorded decision about where code, docs and data live.

## Context
The blueprint's folder tree is illustrative only; the project owner decides. Later tasks refer to folders by the names you record here. Implements blueprint Section 24 (simplified stack).

## What to do
0. **Already decided (pre-created by the project owner):** the Python service is `services/market-data/` (package `market_data`, Python 3.14, uv, Alembic migrations in `services/market-data/migrations/`, poe tasks in `pyproject.toml`); the database is the host's native PostgreSQL service on `localhost:5432` (no Docker); the git-ignored data folder is `data/` at the repository root. Do not rename these; verify them instead.
1. Decide the remaining folder names for: (c) domain docs, (e) benchmark results, (f) ADRs. Suggested: `docs/02-domain/`, `docs/03-benchmarks/`, `docs/04-adr/`. You may choose differently.
2. Create those folders.
3. Confirm PostgreSQL 18 runs as a system service on port 5432 (`uv run poe db-check`). Docker is not used.
4. Create `.env.example` with variable names and dummy values (including `DATABASE_URL`); add `.env` to `.gitignore`.
5. Add `data/` (the raw/curated path you chose) to `.gitignore`.
6. Create the Python environment with `uv sync` inside `services/market-data/` (Python 3.14). Runtime dependencies: `alembic`, `sqlalchemy`, `psycopg[binary]`, `polars`, `pyarrow`, `exchange-calendars`, `httpx`, `python-dotenv`. Dev dependencies: `pytest`, `pytest-cov`, `poethepoet`.
7. Run `uv run poe db-init` once (asks for sudo) to create role and database `marketlab` from `.env`. The schema `market` is created automatically by `migrations/env.py` the first time `uv run poe migration-run` runs (Alembic's version table lives in `market`). Do **not** create the `app` schema: it belongs to NestJS and is created by that service later.
8. Write the chosen layout in `sprints/current_status.md` under "Repository layout in use".

## Where to do it
- Folder / file: repository root; decide names in step 1.
- Technology: native PostgreSQL service, uv, Python.
- Database schema/ownership: `market` owned by the Python service. `app` is owned by NestJS and is not created this sprint.

## Inputs
None.

## Deliverables

- `services/market-data/pyproject.toml` with dependencies and poe tasks (already created; verify it).
- Layout decision recorded in `current_status.md`.

## Acceptance criteria / tests
- [ ] `uv run poe db-check` reports accepting connections, and `uv run poe db-psql` then `SELECT version();` returns PostgreSQL 18.
- [ ] After `uv run poe migration-run` (with at least one migration), `\dn` shows schema `market`, and `market.alembic_version` exists.
- [ ] `uv run poe migration-new test` creates `migrations/versions/0001_test.py`, then the next call creates `0002_...`; delete these two test files afterwards.
- [ ] `uv run python -c "import polars, psycopg, exchange_calendars, alembic"` succeeds from `services/market-data/`.
- [ ] `git status` (once the repo is initialised) shows neither `.env` nor the data folder as untracked.
- [ ] Re-running `uv run poe db-init` changes nothing (idempotent); `DROP DATABASE marketlab` followed by `db-init` and `migration-run` rebuilds an identical schema.
