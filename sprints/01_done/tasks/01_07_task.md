# Task 01_07: Build the idempotent loader with quarantine

**Sprint:** 01     **Depends on:** 01_04, 01_06     **Size:** L
**Concepts to read first:** [01_05 Idempotent ingestion](../concepts/01_05_idempotent-ingestion-and-parquet.md), [01_06 Data quality](../concepts/01_06_data-quality-validation.md)

## Goal
Raw Parquet bars and corporate actions load into PostgreSQL; loading twice changes nothing; invalid rows are quarantined with reasons.

## Context
Blueprint 8.1 steps 4-9 and 8.2 (idempotency).

## What to do
1. Create a `load` module with `load_bars(raw_file, manifest)`.
2. Verify the manifest hash against the file before reading (reuse `verify` from 01_04); abort on mismatch.
3. Read with an explicit Polars schema; normalise column names and cast types; map `symbol` to `instrument_id` (unknown symbol -> quarantine with reason `unknown_symbol`).
4. Apply Python-side hard-rule checks (same rules as the DB CHECKs); failing rows go to `market.bar_quarantine` with a `reason`; they are never silently dropped.
5. Insert valid rows in batches (e.g. 10,000 rows) using `COPY` into a temp table followed by `INSERT ... ON CONFLICT (instrument_id, trade_date, source) DO UPDATE SET ... WHERE existing values differ`, so unchanged rows are not rewritten.
6. Create an `ingestion_job` row at start (`running`), update with counts and `succeeded`/`failed` at the end (also on exception).
7. Enforce the reconciliation `rows_read = inserted + updated + unchanged + rejected` and fail the job if violated.
8. Implement `load_corporate_actions` the same way.
9. Add a command: `load --universe universe_v1.csv`.

## Where to do it
- Folder / file: Python code folder, module `load`.
- Technology: Python, Polars, psycopg (COPY).
- Database schema/ownership: writes to `market` only.

## Inputs
Raw files and manifests from 01_04; schema from 01_06.

## Deliverables
- Loader module and command; loaded `market.bar_daily` and `market.corporate_action`.

## Acceptance criteria / tests
- [ ] **Idempotency test:** load all files, record row count and a checksum (`md5` of ordered `string_agg` of key columns); load again; both are identical, and the second job reports `rows_inserted = 0` and `rows_updated = 0`.
- [ ] **Revision test:** change one price in a copy of a raw file (with a new manifest), load; exactly 1 row `updated`; the others `unchanged`.
- [ ] **Quarantine test:** a file containing 3 bad rows (high < close; negative volume; unknown symbol) results in `rows_rejected = 3` and 3 quarantine rows with distinct reasons.
- [ ] **Failure test:** simulate an exception mid-load; the job is `failed` with `error` set and no partial batch is committed.
- [ ] **Reconciliation holds** for every job (assert in a query).
- [ ] Hash-mismatch test: tampered raw file -> load refuses to start.

## Benchmark
Record loader throughput (rows/s) for the full universe, wall time, and database size after load, in the status log.

## Out of scope
Parallel loading, streaming ingestion, adjusting prices.
