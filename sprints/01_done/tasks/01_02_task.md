# Task 01_02: Write the domain glossary and the data-dictionary skeleton

**Sprint:** 01     **Depends on:** 01_01     **Size:** M
**Concepts to read first:** [01_01 OHLCV](../concepts/01_01_ohlcv-and-candles.md), [01_02 Sessions](../concepts/01_02_sessions-calendars-and-time.md), [01_03 Corporate actions](../concepts/01_03_corporate-actions-and-adjusted-prices.md), [01_04 Provenance](../concepts/01_04_data-provenance-and-licensing.md)

## Goal
A written vocabulary and a column-level description of the tables this sprint will create, so code is written from definitions rather than guesses.

## Context
Blueprint Phase 1 deliverables: domain glossary and data dictionary. Glossary terms later become a data model for lessons.

## What to do
1. In the docs folder (task 01_01), create `glossary.md`. Each entry: term, one-sentence definition, one example, level (beginner/intermediate), related terms, source link.
2. Write at least 25 terms: stock, ETF, index, exchange, broker, market maker, bid, ask, spread, volume, liquidity, market order, limit order, stop order, OHLCV, candlestick, timeframe, trading session, pre-market, after-hours, split, dividend, ex-dividend date, delisting, survivorship bias, look-ahead bias, adjusted price, raw price.
3. Mark each term as **mechanic** (established fact) or **interpretation** (debated). Everything this sprint should be a mechanic.
4. Create `data-dictionary.md` with one section per table planned in task 01_06: `instrument`, `bar_daily`, `corporate_action`, `ingestion_job`, `bar_quarantine`, `data_quality_result`.
5. For each column list: name, type, unit, nullable, meaning, example, and which glossary term it relates to. Mark types as *planned* until 01_06 is done.
6. Add a "Sources" section stub (filled in 01_03).

## Where to do it
- Folder / file: the domain docs folder from 01_01.
- Technology: Markdown.

## Inputs
Blueprint sections 3.1-3.3, 8, 11.

## Deliverables
- `glossary.md` (>= 25 terms), `data-dictionary.md` (6 tables).

## Acceptance criteria / tests
- [ ] Every glossary term has definition, example, source and mechanic/interpretation label.
- [ ] Every planned column in the dictionary has type, nullability and meaning.
- [ ] A reviewer who did not write it can answer from the docs alone: "Is `trade_date` an instant?" (No: exchange-local trading date.) and "Are stored prices adjusted?" (No: raw.)

## Benchmark
Not applicable.

## Out of scope
ICT/SMC terms, fundamentals, options.

## Notes for the implementer
Cite Investor.gov or FINRA first; use Investopedia only as a secondary source.
