# Task 05_02: Resumable Tiingo downloader

**Sprint:** 05     **Depends on:** 05_01     **Size:** M
**Concepts to read first:** [05_04](../concepts/05_04_rate-limited-apis-and-resumable-downloads.md), [05_02](../concepts/05_02_vendor-corporate-actions-and-raw-vs-adjusted.md)

## Goal
`market-data tiingo-download` fetches daily records for the 53 universe symbols from a long start date into `data/raw/tiingo/`, with manifests, within the free-tier request limits, and can be rerun until complete.

## Context
Blueprint 25.1 and 25.6 item 2 (cross-check source). Free limits (read 2026-11-08): 50 requests/hour, 1,000/day, 500 unique symbols/month. Each symbol needs one request.

## What to do
1. Implement `tiingo_fetch(symbol, start, end, token)`: `GET https://api.tiingo.com/tiingo/daily/<symbol>/prices?startDate=...&endDate=...` with the token in the `Authorization: Token ...` header (never in the URL), 30 s timeout, JSON response.
2. Implement `download_tiingo(symbols, start="2005-01-03", end=None, max_requests=45, force=False)`: for each symbol without a matching manifest, request once, write the JSON (as Parquet or JSON; record the choice) and a manifest (provider `tiingo`, endpoint, redacted parameters, retrieved_at, row_count, sha256, tool version, licence note "Tiingo Starter: internal use only"). Stop when `max_requests` is reached.
3. Handle errors: HTTP 429 stops the run with the message "quota reached; rerun later" (exit code 3) and keeps all finished files; 404 for a symbol is recorded as `not_found` in a small status file and skipped; 5xx retried up to 3 times with backoff; a failed run never overwrites an existing file (as in Sprint 01).
4. Save a one-line run summary (requested, skipped, written, failed, stopped_by) to `data/reports/tiingo-download-<timestamp>.json`.
5. Add the CLI command and extend `market-data verify` to cover the `tiingo` tree.
6. Document the two-run procedure (rerun after an hour) in the service README.

## Where to do it
- Folder / file: `services/market-data/src/market_data/download_tiingo.py` (new), `cli.py`, `tests/test_download_tiingo.py`; raw files in `data/raw/tiingo/` (git-ignored).
- Technology: Python, httpx, existing `manifest.py`.
- Database schema/ownership: none.

## Inputs
- `config/universe_v1.csv` (53 symbols); `TIINGO_API_KEY` (live run only).

## Deliverables
- Downloader module, CLI command, tests, README section, raw files and manifests for all available symbols after the live runs.

## Acceptance criteria / tests
- [ ] With a mocked HTTP layer and `max_requests=5` on 12 symbols exactly 5 requests are made; a rerun makes 5 more and skips the 5 finished; a third makes 2 and skips 10.
- [ ] A mocked 429 on the 3rd request stops the run, leaves 2 complete files, exits with code 3 and the message above.
- [ ] Negative test: the fake key string never appears in any file under the temp data dir, in the run summary, in logs or in exception text.
- [ ] A failed request never replaces an existing file (checksums before and after are equal).
- [ ] `market-data verify` reports every tiingo file `ok` after the live runs (needs the real key; record the result).
- [ ] Live run: number of symbols downloaded, number not found, first date and bar count per symbol (table in the completion note).
- [ ] Standing invariants: idempotency (rerun writes nothing new), reconciliation (summary counts add up to the symbols requested).

## Out of scope
- Loading into PostgreSQL (05_03); other vendors; intraday data.

## Notes for the implementer
Keep a margin below 50 requests per hour. Do not request symbols outside the universe: the monthly unique-symbol cap is 500.
