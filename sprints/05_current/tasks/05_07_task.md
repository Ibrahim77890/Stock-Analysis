# Task 05_07: Excess-return Sharpe and VIX regimes

**Sprint:** 05     **Depends on:** 05_05, 05_06     **Size:** M
**Concepts to read first:** [05_05](../concepts/05_05_risk-free-rate-and-macro-series-as-of.md)

## Goal
Backtest results can report Sharpe on excess returns over the 3-month Treasury yield (known the day before), and the regime breakdown can use VIX buckets, with no use of same-day or later macro values.

## Context
Sprints 03 and 04 set the risk-free rate to 0; blueprint 25.4 and 23.2 (regime breakdown) call for FRED data.

## What to do
1. Implement `daily_risk_free(conn, dates)` returning `rf_t = (y / 100) / 252` where `y` is `macro_asof(DGS3MO, t, strict=True)`; raise `LookupError` if a date precedes the first observation.
2. Implement `excess_sharpe(equity, rf_daily)` in `metrics.py`: `mean(r - rf) / std(r - rf, ddof=1) x sqrt(252)`; `None` when std is 0 or fewer than 2 returns. Keep `sharpe` unchanged.
3. Extend `full_run` with an optional `rf` argument adding `sharpe_excess` to both strategy and benchmark metrics; the API/CLI default stays `rf = None` (old output unchanged).
4. Add `regime_labels(..., by="vix")` using fixed buckets from the previous trading day's `VIXCLS` (`low` < 15, `medium` 15 to 25, `high` >= 25; `unknown` if there is none), and extend `regime_breakdown` (same reconciliation).
5. Document the conventions in `docs/02-domain/backtest.md` and `validation.md`, including the FRED attribution notice.

## Deliverables

## Acceptance criteria / tests
- [ ] With `rf = 0` every day, `sharpe_excess == sharpe` exactly.
- [ ] Golden: 5 returns and a constant rf of 0.0002 give the hand-computed excess Sharpe.
- [ ] Negative test: changing today's DGS3MO value does not change today's `rf_t` (it uses the previous day) but changes the next day's.
- [ ] Negative test: VIX labels for a day never change when only that day's or later VIX values are altered (fuzz 50 days in a throwaway database copy).
- [ ] `daily_risk_free` before the first observation raises `LookupError`; a `NULL` day uses the last non-null value.
- [ ] Reconciliation: VIX regime growth factors multiply to the run's total growth (1e-9) on real SPY and AAPL.
- [ ] Real run: AAPL and SPY 20/50, plain Sharpe vs excess Sharpe, and the VIX regime table, recorded in the completion note.
- [ ] Standing invariants: causality, replay boundary, reconciliation.

## Out of scope
- Time-varying cash earning interest inside the engine (the engine's idle cash still earns 0; state the effect), factor regressions, Fama-French data.

## Notes for the implementer
The engine's cash earns nothing while the metric subtracts a positive rf; this biases excess Sharpe of in-and-out rules downward. Say so in the docs.
