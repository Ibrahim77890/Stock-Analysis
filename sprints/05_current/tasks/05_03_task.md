# Task 05_03: Load Tiingo bars and corporate actions as a second source

**Sprint:** 05     **Depends on:** 05_02     **Size:** L
**Concepts to read first:** [05_02](../concepts/05_02_vendor-corporate-actions-and-raw-vs-adjusted.md), [05_01](../concepts/05_01_multi-source-data-and-reconciliation.md)

## Goal
Raw Tiingo prices land in `market.bar_daily` with `source = 'tiingo'` and its splits and dividends in `market.corporate_action`, through the same validated, idempotent, quarantine-aware loader as Alpaca, without touching the Alpaca rows.

## Context
Sprint 01's loader already validates, quarantines and reconciles; the `source` column is part of every key. Only the normalisation differs.

## What to do
1. Implement `normalise_tiingo(records, symbol)` -> `(bars, actions)`: take the date part of `date` without time-zone conversion; keep only raw `open, high, low, close, volume`; ignore every `adj*` field; `divCash > 0` -> a dividend action with `cash_amount`; `splitFactor != 1` -> a split action (`split_from = 1`, `split_to = splitFactor`).
2. Reuse `load.validate_bars` and `load.validate_actions`; invalid rows go to `market.bar_quarantine` with the existing reasons.
3. Reuse the job machinery (`market.ingestion_job` with `source = 'tiingo'`, file hash check against the manifest, one transaction per file, reconciliation `read = inserted + updated + unchanged + rejected`).
4. Add the CLI command `market-data tiingo-load` and a loader test suite with fixture records (AAPL 4-for-1 day, a dividend day, a bad bar with low = 0, a duplicate date).
5. Run the live load, then a second time to prove idempotency.
6. Extend `docs/02-domain/data-dictionary.md` (Tiingo row semantics, date rule, volume meaning) and the data profile with Tiingo per-symbol bar counts and first dates.

## Where to do it
- Folder / file: `services/market-data/src/market_data/load.py` (generalise) or `load_tiingo.py` (new; record the choice), `cli.py`, `tests/test_load_tiingo.py`.
- Technology: Python, Polars, psycopg 3.
- Database schema/ownership: writes `market.bar_daily`, `market.corporate_action`, `market.bar_quarantine`, `market.ingestion_job` with `source='tiingo'`. No migration expected; if one is needed it is `0009` and recorded.

## Inputs
- Raw files from 05_02; a throwaway database for tests (`TEST_DATABASE_URL`).

## Deliverables
- Loader code, CLI command, tests, dictionary and profile updates, loaded data.

## Acceptance criteria / tests
- [ ] Fixture AAPL split record yields one split action with `split_to = 4.0`, and a dividend record one dividend action; `adjClose` is never read (a test with deliberately different `adjClose` values proves the close column holds the raw `close`).
- [ ] Negative test: a record with `low = 0` is quarantined and not inserted; a duplicate date is rejected with a reason.
- [ ] Idempotency: loading the same file twice reports 0 inserted and 0 updated the second time and row counts are equal.
- [ ] Isolation: after the Tiingo load, the Alpaca rows are byte-identical (compare a hash of `market.bar_daily WHERE source='alpaca'` before and after).
- [ ] Reconciliation: every job satisfies `read = inserted + updated + unchanged + rejected`.
- [ ] Date test: a record dated `2021-03-05T00:00:00.000Z` is stored as 2021-03-05.
- [ ] Live: per-symbol row counts and the share of symbols whose first date is before 2010 recorded in the completion note.
- [ ] Standing invariants: idempotency, reconciliation.

## Out of scope
- Using the vendor's adjusted columns; merging sources; intraday data.

## Notes for the implementer
The structural test from Sprint 02 allows only `read.py`, `load.py` and `quality.py` to touch `market.bar_daily`; if you add `load_tiingo.py`, extend the allowed list and keep the negative test for it.
