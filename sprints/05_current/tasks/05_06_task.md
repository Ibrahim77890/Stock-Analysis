# Task 05_06: Total-return price basis in the backtest, checked against the vendor

**Sprint:** 05     **Depends on:** 05_03     **Size:** M
**Concepts to read first:** [05_03](../concepts/05_03_total-return-and-dividend-adjustment.md), [05_02](../concepts/05_02_vendor-corporate-actions-and-raw-vs-adjusted.md)

## Goal
A backtest can run on split-and-dividend-adjusted prices (`price_basis = split_dividend`), proven causal, without changing the hashes of existing runs, and our as-of adjustment is cross-checked against Tiingo's adjusted close.

## Context
Sprint 03 ignores dividends (a known limitation). Sprint 02 already computes `split_dividend` as of a date; the scale-invariance argument of ADR 0009 extends to it.

## What to do
1. Add `price_basis` (`split` default, `split_dividend`) to `BacktestSpec`; `backtest_from_db` loads `get_bars(..., adjustment=price_basis, source=spec.source)`; add `source` (default `alpaca`) to the spec the same way.
2. Update `research.canonical_spec` so `price_basis` and `source` are included **only when not the defaults**; add a test that the Sprint 03 saved-run hashes (AAPL `782fe346...`, SPY `15e2afd1...`) are unchanged.
3. Extend `check_engine_truncation` runs to `split_dividend`, on AAPL across the 2020-08-31 split and at least two dividend ex-dates (find them in `market.corporate_action`), and on SPY.
4. Add the external check `adjustment_vs_vendor(conn, symbol)`: using the loaded raw Tiingo `adjClose` values (add them to the raw file read, **not** to the database) compute `ours_asof_end / vendor_adjClose` per date; report median, spread (p5..p95) and the max deviation; expect a near-constant ratio.
5. Produce the comparison table (price basis `split` vs `split_dividend`; buy-and-hold and SMA 20/50; AAPL and SPY; Tiingo long window and Alpaca window) in `docs/02-domain/backtest.md`.
6. Update the limitation line "no dividends in returns" to say where it still applies.

## Where to do it
- Folder / file: `services/market-data/src/market_data/backtest.py`, `research.py`, `reconcile.py` (or `adjust_check.py`), `tests/test_total_return.py`, `docs/02-domain/backtest.md`.
- Technology: Python, Polars.
- Database schema/ownership: no migration; the spec JSON in `research.backtest_run` gains optional keys.

## Inputs
- 05_03 loaded data; Sprint 02 `adjust.py`.

## Deliverables
- Spec fields, truncation tests, vendor check, docs table.

## Acceptance criteria / tests
- [ ] Hashes of the two Sprint 03 saved runs recompute to the same values (test reads them from `docs/02-domain/backtest-worked-example.md` or constants).
- [ ] Changing `price_basis` or `source` changes the config hash (parametrised); the defaults do not appear in the canonical spec.
- [ ] Truncation test passes for `split_dividend` on AAPL (50 random cuts plus cuts around the split and two ex-dates) at relative tolerance 1e-9; a leaky variant that uses the end-date factor per bar differently fails it (negative test).
- [ ] Accounting identity holds with `split_dividend`.
- [ ] Golden: a 6-bar frame with one dividend gives the hand-computed adjusted closes and total return.
- [ ] Vendor check: report the spread of `ours / vendor` for 5 dividend-paying symbols; state the tolerance used and whether it was met, whatever the result.
- [ ] Standing invariants: causality, reproducibility, reconciliation.

## Out of scope
- Dividend reinvestment timing other than at the ex-date close; taxes; withholding.

## Notes for the implementer
Vendor and our series use the same idea but may round differently; a systematic constant offset of a few bps is acceptable, a drifting ratio is a finding.
