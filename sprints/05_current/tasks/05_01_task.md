# Task 05_01: Source terms, multi-source policy (ADR 0013) and key handling

**Sprint:** 05     **Depends on:** none     **Size:** M
**Concepts to read first:** [05_01](../concepts/05_01_multi-source-data-and-reconciliation.md), [05_04](../concepts/05_04_rate-limited-apis-and-resumable-downloads.md)

## Goal
The second-source decisions are written down (ADR 0013), the licence terms of Tiingo and FRED are recorded with retrieval dates, and the code can check that the two new keys exist without ever printing them.

## Context
Blueprint 25.1 (Tiingo as cross-check source), 25.4 (FRED), 25 preamble ("public does not mean redistributable"). Keys are free and are put in the git-ignored `.env` by the owner; placeholders are in `.env.example`.

## What to do
1. Re-read the Tiingo pricing page and the FRED terms of use; quote the key sentences (free-tier limits, "Internal Use Only", third-party copyright, attribution notice) in the Sources table of `docs/02-domain/data-dictionary.md` with the retrieval date.
2. Write ADR `docs/04-adr/0013-second-source-and-macro-policy.md`: rows are keyed by `source`; a series is read from one source only (no splicing); primary source per use (Alpaca for IEX-venue studies and volume-free work, Tiingo for long-history price studies); raw data and database stay local; vendor adjusted columns are never loaded; macro data stay local and FRED attribution is shown wherever FRED-derived numbers are displayed.
3. Add `config.tiingo_key()` and `config.fred_key()` to `config.py`: raise a clear `RuntimeError` naming the missing variable (never the value).
4. Add the CLI command `market-data check-keys` that reports for each of `ALPACA`, `TIINGO`, `FRED` whether the key is set and its length class (e.g. "set, 40 chars"), and with `--ping` makes one cheap authenticated request per set key and reports `ok`/`rejected`/`unreachable`. Exit code 2 if a key required for the sprint is missing.
5. Verify `.env.example` lists `TIINGO_API_KEY` and `FRED_API_KEY` (already added) and that `.env` stays git-ignored.

## Where to do it
- Folder / file: `docs/04-adr/0013-second-source-and-macro-policy.md`, `docs/02-domain/data-dictionary.md`, `services/market-data/src/market_data/config.py`, `cli.py`, `tests/test_keys.py`.
- Technology: Python, httpx (existing), Typer/argparse as already used by `cli.py`.
- Database schema/ownership: none.

## Inputs
- https://www.tiingo.com/about/pricing , https://www.tiingo.com/documentation/end-of-day , https://fred.stlouisfed.org/docs/api/terms_of_use.html .
- The owner's keys in `.env` (not needed for the tests; they use fake keys).

## Deliverables
- ADR 0013, updated Sources table, `config` accessors, `check-keys` command, tests.

## Acceptance criteria / tests
- [ ] Missing key: `tiingo_key()` raises `RuntimeError` whose message contains the variable name and not any value.
- [ ] Negative test: with a fake key `KEY-ABC-123456` set, the output of `check-keys` (with the HTTP layer mocked) and all log lines do not contain the key string.
- [ ] `check-keys --ping` against a mocked 401 reports `rejected`; against a mocked network error reports `unreachable`; neither raises.
- [ ] `git check-ignore .env` prints `.env`; `git ls-files | grep -E "^\.env$"` prints nothing.
- [ ] The data dictionary Sources table contains the quoted Tiingo and FRED terms with retrieval date and the CBOE copyright caution for VIXCLS.
- [ ] Standing invariant: reproducibility (the policy is stated before any data are downloaded).

## Out of scope
- Downloading data (05_02, 05_05); reading Tiingo's full terms of service PDF if one exists (record whether it was read).

## Notes for the implementer
If a terms page cannot be fetched, write "not read" in the table instead of guessing.
