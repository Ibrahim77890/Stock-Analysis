# Task 02_03: Adjusted reads through get_bars

**Sprint:** 02     **Depends on:** 02_02     **Size:** S
**Concepts to read first:** [02_01 Adjusted prices as-of](../concepts/02_01_adjusted-prices-as-of-and-look-ahead.md), [02_04 Golden and property testing](../concepts/02_04_golden-and-property-based-testing.md)

## Goal
`get_bars` can return raw, split-adjusted or split-and-dividend-adjusted bars, always as of a date that the caller controls.

## Context
Sprint 01's `get_bars` returns raw bars with a `max_date` cap. Charts and indicators need adjusted series, but only computed as-of the cursor.

## What to do
1. Extend `get_bars(conn, symbol, start, end, source, max_date, adjustment='raw')` so that when `adjustment != 'raw'` it loads the instrument's actions with `ex_date <= effective_end` and calls `adjust_bars` from 02_02 with `as_of = effective_end`.
2. Reject unknown `adjustment` values with `ValueError`.
3. Add the `adjustment` and `as_of` (the effective end date) as columns or as attributes of the result, so the consumer can show them.
4. Keep `adjustment='raw'` byte-identical to Sprint 01 behaviour (existing tests unchanged).
5. Add tests on the real data: AAPL 2020-08-25..2020-09-04 split-adjusted as of 2020-09-04 has factor 0.25 on bars before 2020-08-31 and 1 on later bars; with `max_date=2020-08-28` the same call returns raw-equal values (the split is not yet visible).
6. Add the truncation test against a temporary copy of the database (or a schema) that contains bars and actions only up to `D`: results equal for 20 random `D`.

## Where to do it
- Folder / file: `services/market-data/src/market_data/read.py`, tests in `services/market-data/tests/`.
- Technology: Python, Polars, psycopg.
- Database schema/ownership: reads `market.bar_daily`, `market.corporate_action`; no writes.

## Inputs
Task 02_02 functions; loaded data.

## Deliverables
- Extended `get_bars` and its tests; docstring that states what as-of means.

## Acceptance criteria / tests
- [ ] Existing Sprint 01 `get_bars` tests pass unchanged.
- [ ] The AAPL case returns the hand-computed factors (0.25 before the ex-date, 1 after).
- [ ] With `max_date` before the ex-date, no adjustment is applied.
- [ ] Truncation test passes for 20 random cut dates; a negative test with a leaky variant fails.
- [ ] `adjustment='bogus'` raises `ValueError`; unknown symbol still raises `UnknownSymbolError`.

## Benchmark
Record `get_bars` time for one symbol, full history, raw vs split-adjusted (informational).

## Out of scope
Caching adjusted series, new tables.

## Notes for the implementer
All actions for the symbol are small (tens of rows); fetching them per call is fine.
