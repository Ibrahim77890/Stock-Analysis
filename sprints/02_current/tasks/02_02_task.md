# Task 02_02: Implement as-of corporate-action adjustment factors

**Sprint:** 02     **Depends on:** none     **Size:** M
**Concepts to read first:** [02_01 Adjusted prices as-of](../concepts/02_01_adjusted-prices-as-of-and-look-ahead.md), [02_04 Golden and property testing](../concepts/02_04_golden-and-property-based-testing.md), [01_03 Corporate actions](../../01_done/concepts/01_03_corporate-actions-and-adjusted-prices.md)

## Goal
A pure, tested function that turns raw bars plus corporate actions plus an `as_of` date into adjusted OHLCV, without using any action after `as_of`.

## Context
Blueprint 23.3 item 1 and ADR 0001: raw prices are stored; adjusted series are computed as-of on demand. No adjustment code exists yet.

## What to do
1. Create a module `adjust` in the market-data package (project owner may choose another name; record it in the status log).
2. Define modes: `raw`, `split`, `split_dividend`.
3. Write `split_factors(bar_dates, splits, as_of)` returning one factor per bar date: the product of `split_from / split_to` over splits with `bar_date < ex_date <= as_of`.
4. Write `dividend_factors(bars, dividends, as_of)`: for each dividend with `ex_date <= as_of`, factor `1 - cash_amount / close_on_last_session_before_ex_date`, applied to bars before the ex-date. Use raw closes.
5. Write `adjust_bars(bars, actions, as_of, mode)` returning the frame with adjusted `open, high, low, close`, and `volume` multiplied by the inverse split factor (document this choice), plus a `factor` column. Bars after `as_of` are dropped.
6. Keep full float precision; do not round factors.
7. Write golden tests with the arithmetic in comments: closes 400 and 100 with a 4-for-1 on day 2 (as of day 1 and day 2); an invented 3-bar series with a 2-for-1 split plus a dividend; GE 1-for-8 reverse split (factor 8).
8. Write real-data tests on AAPL (2020-08-31, 4-for-1) and NVDA (2024-06-10, 10-for-1): adjusted return across the ex-date is within +/-15% and raw return is about -74% / -90%.
9. Write the causality property test: for random `D` in the data range, adjusting with all actions and adjusting with only actions `ex_date <= D` give identical output for every bar `<= D`.
10. Write a negative test: a deliberately leaky implementation (uses actions after `as_of`) must make the property test fail.

## Where to do it
- Folder / file: `services/market-data/src/market_data/adjust.py`, tests in `services/market-data/tests/`.
- Technology: Python, Polars; Hypothesis optional (a seeded loop is acceptable).
- Database schema/ownership: none (pure functions; no database access).

## Inputs
Raw bars and corporate actions loaded in Sprint 01 (for the real-data tests, read through `get_bars` and a small helper that reads actions).

## Deliverables
- `adjust.py` with the three functions and mode enum.
- Golden, real-data and property tests; a short section in the data dictionary describing the modes.

## Acceptance criteria / tests
- [ ] The day-1 and day-2 golden cases return 400 / 100,100 style values exactly as hand-computed.
- [ ] AAPL and NVDA adjusted returns are within +/-15%; raw returns match -74% and -90% within 2 points.
- [ ] Causality property test passes for 100 random `as_of` dates.
- [ ] The leaky implementation fails the property test.
- [ ] Reverse split (GE) gives a factor above 1 and still positive prices.
- [ ] Standing invariant 26.2 item 2: no function returns a mixed adjusted/raw frame (the `mode` is a column or documented).

## Benchmark
Not applicable.

## Out of scope
Spin-offs, mergers, symbol changes, dividends other than cash.

## Notes for the implementer
Apply the factor to bars strictly before the ex-date. Split dates and ratios come from `market.corporate_action`; treat the table, not memory, as the source.
