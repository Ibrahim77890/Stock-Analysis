# Task 02_06: Read-only HTTP API for bars with cursor and adjustment

**Sprint:** 02     **Depends on:** 02_03, 02_04, 02_05     **Size:** M
**Concepts to read first:** [02_05 HTTP read API with FastAPI](../concepts/02_05_http-read-api-with-fastapi.md), [02_02 Replay cursor](../concepts/02_02_replay-cursor-and-leakage-testing.md)

## Goal
The market-data service answers `GET /bars` over HTTP on `127.0.0.1`, with the cursor and the adjustment enforced by the layers below, and a checked OpenAPI contract.

## Context
Blueprint 24 (schema ownership) and 12 (API sketch). The future NestJS service and the frontend need a narrow contract instead of database access.

## What to do
1. Add `fastapi` and `uvicorn` (and `httpx` already present for tests) to `pyproject.toml`; record the addition in the status log.
2. Create an `api` module with `GET /health`, `GET /instruments`, and `GET /bars?symbol&start&end&adjustment=raw|split|split_dividend&cursor`.
3. `/bars` calls `replay`/`get_bars` only; the handler contains no SQL. When `cursor` is absent it defaults to `end`.
4. Map errors: 404 unknown symbol, 400 `start > end`, 422 bad types or unknown adjustment.
5. Add an optional `indicators` query parameter (for example `sma:20,ema:50`) that appends causal indicator columns computed on adjusted bars up to the cursor.
6. Use response models (Pydantic) with ISO dates and numbers; replace NaN with null.
7. Add a command `uv run market-data serve --port 8000` that binds to `127.0.0.1` only.
8. Export the OpenAPI document to `docs/02-domain/openapi-market-data.json` and add a test that fails if the live schema differs from the committed file.
9. Write TestClient tests: happy path, unknown symbol, bad dates, bad adjustment, cursor before `start` returns an empty list, cursor fuzz (200 random cursors; no date after the cursor), SQL injection string in `symbol` returns 404 and changes nothing.

## Where to do it
- Folder / file: `services/market-data/src/market_data/api.py`, `cli.py` (serve command), tests in `services/market-data/tests/`.
- Technology: FastAPI, uvicorn, Pydantic, psycopg.
- Database schema/ownership: reads `market` only; read-only endpoints.

## Inputs
`get_bars`, `replay`, `indicators`.

## Deliverables
- `api.py`, `serve` command, committed OpenAPI file, tests, README lines.

## Acceptance criteria / tests
- [ ] `GET /health` returns 200; the server refuses to bind to anything but 127.0.0.1 unless a flag is given (and the flag is not documented as safe).
- [ ] 404, 400 and 422 cases behave as specified.
- [ ] Cursor fuzz over HTTP: no response contains a date after the cursor.
- [ ] The OpenAPI contract test passes and fails when a field is renamed (demonstrate once).
- [ ] An injection attempt in `symbol` leaves row counts unchanged.
- [ ] Standing invariants: replay boundary and causality hold over HTTP.

## Benchmark
Informational: p50/p95 latency of `GET /bars` (one symbol, one year) over 200 requests, warm, with and without an indicator column.

## Out of scope
Authentication, NestJS, frontend, write endpoints, caching.

## Notes for the implementer
Use query parameters in SQL, never string formatting. One connection per request is acceptable at this scale.
