# Task 05_04: Cross-source reconciliation (Alpaca IEX vs Tiingo)

**Sprint:** 05     **Depends on:** 05_03     **Size:** M
**Concepts to read first:** [05_01](../concepts/05_01_multi-source-data-and-reconciliation.md), [05_06](../concepts/05_06_long-history-and-what-it-changes.md)

## Goal
A reproducible report says, per symbol and overall, where the two sources agree and disagree on prices, dates and corporate actions, with the tolerance fixed in advance.

## Context
Blueprint 25.6 item 2 and 26.1 (cross-check two sources; flag, don't delete).

## What to do
1. Write the tolerances in the ADR 0013 appendix before running anything: a close is a *mismatch* if the absolute relative difference exceeds 1.0% (100 bps); a *notice* above 0.25%; volume ratios are reported but never flagged; an action *agrees* if ex-date is equal and the split ratio or cash amount is within 0.5%.
2. Implement `reconcile_bars(conn, symbol, a="alpaca", b="tiingo", start=None, end=None)` using `read.get_bars(..., source=...)` raw prices: returns matched dates, only-in-A, only-in-B, quantiles (p50/p90/p99/max) of absolute relative differences for open, high, low, close, volume ratio quantiles, and the list of mismatch dates (at most 20 per symbol).
3. Implement `reconcile_actions(conn, symbol, a, b)`: counts of agreeing, disagreeing and one-sided actions with the first 10 examples.
4. Implement `reconcile_universe(conn)` and write `data/reports/reconciliation-<run>.json` and `.md`.
5. Investigate the largest mismatches by hand (at most 5) and write what you found in the completion note (e.g. a stale IEX print, a vendor error); do not change any data.
6. Summarise in `docs/02-domain/data-profile-v1.md` (new section "Cross-source reconciliation").

## Where to do it
- Folder / file: `services/market-data/src/market_data/reconcile.py` (new), `cli.py` command `reconcile`, `tests/test_reconcile.py`.
- Technology: Python, Polars; reads through `read.py` only.
- Database schema/ownership: read-only on `market`; report files under `data/reports/`.

## Inputs
- Both sources loaded (05_03); overlap window 2020-07-27 to 2025-12-31.

## Deliverables
- `reconcile.py`, CLI command, report files, data-profile section, tests.

## Acceptance criteria / tests
- [ ] Golden: two hand-made series of 5 dates with known differences give the hand-computed quantiles, one only-in-A date and one mismatch.
- [ ] Negative test: after altering one Tiingo close in the throwaway database by +5%, the report flags exactly that date as a mismatch and no other.
- [ ] Volume ratios are present in the report and never produce a flag (test).
- [ ] Reproducibility: running the report twice on unchanged data gives identical JSON (apart from the run id and timestamp fields).
- [ ] The tolerances in the code equal those in the ADR appendix (a test parses both).
- [ ] Live: counts of mismatch dates, notices and action disagreements, and the median close difference in bps, recorded in the completion note.
- [ ] Standing invariants: reconciliation (matched + only-in-A = A dates; matched + only-in-B = B dates), reproducibility.

## Out of scope
- Repairing or deleting disagreeing rows; a third source.

## Notes for the implementer
Report honestly if the sources disagree more than expected; that is a finding about IEX data, not a failure of the task.
