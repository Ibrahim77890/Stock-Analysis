# Task 05_05: FRED macro series (risk-free rate and VIX), loaded and read as of a date

**Sprint:** 05     **Depends on:** 05_01     **Size:** M
**Concepts to read first:** [05_05](../concepts/05_05_risk-free-rate-and-macro-series-as-of.md), [05_04](../concepts/05_04_rate-limited-apis-and-resumable-downloads.md)

## Goal
`DGS3MO` and `VIXCLS` are downloaded from FRED with manifests, loaded idempotently into a new table, and can be read with an as-of rule that never returns a later observation.

## Context
Blueprint 25.4 (FRED for risk-free rate and VIX). Needs the free `FRED_API_KEY`.

## What to do
1. Create migration `0009` (`uv run poe migration-new create macro observation table`): `market.macro_observation(series_id text, obs_date date, value numeric(18,6) NULL, source text, ingestion_job_id bigint FK, PRIMARY KEY (series_id, obs_date, source))`, `CHECK (value IS NULL OR value > -1000)`; up, down, up.
2. Implement `fred_fetch(series_id, start, token)` (`https://api.stlouisfed.org/fred/series/observations`, `file_type=json`, units `lin`); the key is a query parameter required by FRED: never log or store the request URL.
3. Implement `download_fred(series=("DGS3MO","VIXCLS"), start="2000-01-01")` writing raw JSON plus manifest (provider `fred`, endpoint without key, retrieved_at, row_count, sha256, licence note and the FRED attribution text).
4. Implement `load_fred(conn)`: `.` -> NULL; dates as given; idempotent upsert; job row with reconciliation.
5. Implement `read.get_macro(conn, series_id, start, end)` and `read.macro_asof(conn, series_id, d, strict=True)`: the latest non-null value with `obs_date < d` (strict) or `<= d`; raises `LookupError` before the first observation.
6. Add CLI commands `fred-download`, `fred-load`, extend `verify`; record the dictionary rows and the attribution notice in the docs.

## Where to do it
- Folder / file: `services/market-data/migrations/versions/0009_*.py`, `src/market_data/macro.py` (new: download/load), `read.py` (macro reads), `cli.py`, `tests/test_macro.py`; raw files in `data/raw/fred/` (git-ignored).
- Technology: Alembic, httpx, Polars, psycopg 3.
- Database schema/ownership: `market.macro_observation` (Python service owns the `market` schema).

## Inputs
- `FRED_API_KEY` (live run only); mocked JSON fixtures for tests, including `"."` values.

## Deliverables
- Migration 0009, macro module, read functions, CLI commands, tests, loaded series, dictionary rows.

## Acceptance criteria / tests
- [ ] Migration up/down/up leaves the same table list; `alembic heads` shows `0009`.
- [ ] `"."` is stored as NULL (not 0); `macro_asof` skips back over it to the previous non-null value (test with a holiday gap).
- [ ] Negative test: `macro_asof(series, d, strict=True)` never returns an observation dated on or after `d` (fuzz 200 random dates over the real series).
- [ ] `macro_asof` before the first observation raises `LookupError`.
- [ ] Idempotency: second load reports 0 inserted and 0 updated.
- [ ] Negative test: the fake key never appears in files, logs, manifests or exceptions.
- [ ] Live: first and last date, observation count and number of NULLs for each series recorded in the completion note; spot-check two values against the FRED web page by hand (record the dates).
- [ ] Standing invariants: idempotency, replay boundary (as-of rule), reconciliation.

## Out of scope
- Other series, Kenneth French factors (deferred), vintage/revision handling (ALFRED).
