# Task 04_08: Expose every validation function in Swagger

**Sprint:** 04     **Depends on:** 04_02, 04_03, 04_04, 04_05, 04_06, 04_07     **Size:** M
**Concepts to read first:** [04_01](../concepts/04_01_overfitting-and-multiple-testing.md), [04_04](../concepts/04_04_sharpe-uncertainty-psr-and-dsr.md)

## Goal
Each function built in this sprint has its own endpoint in a Swagger section "Validation", with inputs that work without the database where the function is pure.

## Context
Continues ADR 0007 and the Sprint 03 pattern: the owner wants to try each function by hand.

## What to do
1. Add a router module (suggest `api_validation.py`, included from `api.py` like `api_backtest.py`) with tag `Validation`:
   - `POST /validation/grid-search` (symbol, window, grid; `record` flag default false; if true creates a study and stores trials).
   - `POST /validation/split-evaluation` (train/test/embargo; `record` flag).
   - `POST /validation/holdout` (study id; one use).
   - `POST /validation/walk-forward` (train/test/embargo, grid; `record` flag).
   - `POST /validation/sharpe-stats` (your own returns, optional number of trials; returns Sharpe, PSR, expected max, DSR; no database).
   - `GET /validation/studies`, `GET /validation/studies/{id}` (trials and the overfitting meter).
   - `POST /validation/universe-scan` and `POST /validation/best-of-n`.
   - `POST /validation/regimes` (symbol, window, spec, `by`).
2. Use Pydantic models with limits (grid at most 400 pairs, replicates at most 500, returns at most 100,000 values) and examples.
3. Map errors: unknown symbol 404; invalid parameters 422/400; second holdout use 409.
4. Refresh `docs/02-domain/openapi-market-data.json` (`uv run market-data export-openapi`); extend the contract test and the tag test in `tests/test_api.py`.
5. Update the service README Swagger table.

## Where to do it
- Folder / file: `services/market-data/src/market_data/api_validation.py`, `api.py`, `tests/test_api_validation.py`, README, `docs/02-domain/openapi-market-data.json`.
- Technology: FastAPI, Pydantic (existing).
- Database schema/ownership: writes `research.study`/`research.trial` only when `record` is true or on the holdout call; no writes to `market`.

## Inputs
- 04_02 to 04_07 functions.

## Deliverables
- Endpoints, refreshed OpenAPI contract, tests, README section.

## Acceptance criteria / tests
- [ ] A test lists every function from 04_02 to 04_07 and the endpoint that exposes it.
- [ ] `/validation/sharpe-stats` with the golden returns from 04_05 returns the golden PSR.
- [ ] Two identical `grid-search` calls with `record: true` create two studies (attempts are counted) and a call with `record: false` writes nothing (row counts checked).
- [ ] Second `/validation/holdout` call for a study returns 409 and adds no trial.
- [ ] Negative tests: grid of 401 pairs 422; `fast >= slow` in the grid 400/422; unknown symbol 404; injection-style symbol changes no row counts in `market` or `research`.
- [ ] Contract test passes; renaming a field is detected (negative test as in Sprint 02).
- [ ] Standing invariant: replay boundary (an `end` date earlier than the data end never returns later dates; fuzz 50 dates).

## Out of scope
- Authentication, background jobs, storing scan and control outputs.

## Notes for the implementer
Start `uv run market-data serve` (loopback only) and call each endpoint once from Swagger; record that you did in the completion note.
