# Task 04_02: Parameter grid search with trial recording

**Sprint:** 04     **Depends on:** 04_01     **Size:** M
**Concepts to read first:** [04_01](../concepts/04_01_overfitting-and-multiple-testing.md)

## Goal
A function evaluates every (fast, slow) pair of a grid on a given bar window, records one trial per pair in the registry, and returns the ranked table plus the number of trials.

## Context
Sprint 03 can score one pair. A search must count itself (blueprint 23.2). The search works on whatever window it is given; the caller (04_03, 04_04) decides that this is the training window.

## What to do
1. Implement `make_grid(fast_values, slow_values)`: all pairs with `fast < slow`; reject empty results, values < 1, duplicates, and more than 400 pairs.
2. Implement `grid_search(bars, base_spec, grid, metric="sharpe")` returning one row per pair (fast, slow, total_return, sharpe, trades) sorted by the metric (nulls last, ties broken by smaller slow then smaller fast) and the best pair. It uses `run_backtest` unchanged; costs come from `base_spec`.
3. Implement `create_study(conn, name, family, symbol)` and `record_trials(conn, study_id, phase, rows, window)` writing one `research.trial` row per evaluated pair in one transaction.
4. Implement `study_summary(conn, study_id)`: number of trials per phase, best train Sharpe, and trials listed.
5. Write a script-free example in the module docstring and in `docs/02-domain/validation.md` (created now, extended later).

## Where to do it
- Folder / file: `services/market-data/src/market_data/validation.py` (new module), tests in `services/market-data/tests/test_validation_search.py`, `docs/02-domain/validation.md`.
- Technology: Python, Polars, psycopg 3, the Sprint 03 engine.
- Database schema/ownership: writes `research.study` and `research.trial` only.

## Inputs
- 04_01 migration; synthetic bars (seeded) and real AAPL/SPY bars.

## Deliverables
- `validation.py` with `make_grid`, `grid_search`, `create_study`, `record_trials`, `study_summary`.
- Tests and docs page.

## Acceptance criteria / tests
- [ ] A 3 x 3 grid with the 5-bar golden data from `tests/test_backtest.py` returns the hand-computed best pair (write the by-hand table in the test comments).
- [ ] The number of recorded trials equals the number of pairs evaluated (e.g. 12 pairs gives 12 rows) and `study_summary` reports it.
- [ ] Re-running the same search in the same study adds trials again (the registry counts attempts; documented) but never edits earlier rows.
- [ ] Determinism: two searches on the same bars give identical tables.
- [ ] Negative tests: empty grid, `fast >= slow`, duplicates, > 400 pairs, unknown metric, unknown study id raise `ValueError`/`LookupError`.
- [ ] Real data: a 5 x 5 grid on SPY from 2020-07-27 (the contiguous window) completes; the best pair is recorded with the number of trials (25) in the completion note.
- [ ] Standing invariants: reproducibility (determinism), reconciliation (trial count equals pairs).

## Benchmark (when relevant)
- Informational: seconds for a 25-pair grid and for a 400-pair grid on 1,366 bars; record the machine. No target.

## Out of scope
- Optimisers other than exhaustive grid, parallelism, other strategies.

## Notes for the implementer
Do not "clean" the registry by deleting weak trials; the whole point is that they count.
